## 三个评审维度

1. 准确（"accuracy"）：摘要里有没有原文不支持或与原文矛盾的说法。包括：数值、单位、误差、方向（升高还是降低、大于还是小于）写错；把作者的声称或推测写成已经证实的结果；把条件、样本或对象说错；原文根本没有的内容。摘要里的概括和换一种说法不算错，只要意思与原文一致。由原文数值直接算出的数（差值、比值、百分比换算等）算对了不算错，算错了算准确性问题；这两种情况都在 "explanation" 里写明是由哪些原文数值算的。
2. 完整（"completeness"）：相对这份摘要的用途，有没有漏掉原文明确给出的最重要的结果、关键条件或关键限制。只看重要的：不要求把原文的每个细节都写进来，次要结果、背景、实现细节没写不算问题。
3. 清楚（"clarity"）：一个没读过这篇论文的读者，能不能看懂每个部分在说什么。包括：没有解释的行话或缩写、指代不明（“该方法”“这一结果”指什么说不清）、语句不通或前后矛盾。能否看懂只取决于摘要本身，不要拿原文去补。

## 严重程度

- "major"（大问题）：会误导读者，或者漏掉了论文最主要的结果。
- "minor"（小问题）：不够精确，或者漏掉的是次要内容，或者只是表达上不够顺。
拿不准是大是小时，选 "minor"。只报告你有把握的问题；没有问题就如实写 "ok"，不要为了显得认真而凑问题。最多报告 8 个问题，挑最重要的。

## 不要评审的内容

格式、长度、公式的写法（`$...$` 怎么写）、标点、是否使用了“原文未说明”这个固定说法，这些由程序另外检查，不要评，也不要因此扣分。也不要评论文本身好不好、结论对不对，只看摘要有没有如实、完整、清楚地反映原文。

## 怎么引用

每个问题都要引用证据，并且必须逐字摘抄，不要改写、不要翻译、不要补省略号：
- "summaryQuote"：摘要里有问题的那一句或那一小段原话，必须逐字出现在“位置”对应的那一部分摘要里。尽量短（一个短句即可）。
- "sourceQuote"：`<paper_data>` 里支持你判断的原话（准确性问题：与摘要冲突或说明正确说法的那一句；完整性问题：被漏掉的内容的那一句），必须逐字出现在 `<paper_data>` 里，公式保持原文写法。
  - 完整性问题必须给出 "sourceQuote"。
  - 准确性问题里，如果摘要的说法在原文里根本找不到对应内容，"sourceQuote" 写 null，并且在 "explanation" 里写明“原文未提及”以及摘要的哪个说法没有依据。
  - 清楚性问题的 "sourceQuote" 通常是 null。
- 空白（空格、换行）的差别不要紧，其余字符必须一致。

## 输出格式

只输出一个 JSON 对象，不要输出 Markdown、代码块、解释或 JSON 之外的任何文字。键名必须完全一致，所有说明用中文：

{"verdicts":{"accuracy":"ok","completeness":"ok","clarity":"ok"},"issues":[{"dimension":"accuracy","severity":"major","location":"…","summaryQuote":"…","sourceQuote":"…","explanation":"…"}]}

- "verdicts"：三个维度各一个判定，取值只能是 "ok"、"minor"、"major"。某个维度的判定必须等于它名下所有问题里最严重的那个；没有问题就是 "ok"。
- "issues"：问题列表，没有问题时是空数组 []。每项包含：
  - "dimension"：只能是 "accuracy"、"completeness"、"clarity"。
  - "severity"：只能是 "minor"、"major"。
  - "location"：问题所在的位置，只能是下面这些之一：{{locations}}。
  - "summaryQuote"、"sourceQuote"、"explanation"：见上。"explanation" 用一两句话说清楚错在哪里、漏了什么或哪里看不懂。
