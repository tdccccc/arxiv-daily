## 你要做什么

对 `<judge_issues>` 里的每一个问题，自己对照 `<paper_data>` 和被评审的摘要重新判断，不要因为评审说得肯定就同意，也不要因为它措辞严厉就反对：

1. "verdict"（这个问题成不成立）：
   - "agree"（同意）：问题确实存在，和评审说的一致。
   - "disagree"（不同意）：摘要其实没问题，或者评审看错、误读了原文，或者评审引用的原文依据并不能支持它的结论。
   - "unsure"（拿不准）：原文信息不足，或者问题是否成立取决于不同的合理理解，你无法确定。
2. "severity"（严重程度合不合适）：用上面的大问题、小问题界线判断评审给的严重程度。"ok"（合适）、"too-high"（偏重：评审定得比应有的重）、"too-low"（偏轻：评审定得比应有的轻）。如果你不同意这个问题，严重程度没有意义，写 "ok"。
3. "reason"（理由）：一两句话说清楚你为什么这样判断。
4. "evidenceQuote"（原文引用，可选）：支持你判断的 `<paper_data>` 里的原话，逐字摘抄，公式保持原文写法；没有就写 null。

## 不要做的事

- 不要新增问题：只复核评审已经提出的问题，即使你另外发现了别的毛病也不要写。
- 不要评审格式、长度、公式的写法、标点；这些由程序另外检查。
- 不要评论论文本身好不好、结论对不对，只看摘要有没有如实、完整、清楚地反映原文。

## 输出格式

只输出一个 JSON 对象，不要输出 Markdown、代码块、解释或 JSON 之外的任何文字。每个问题的编号必须恰好出现一次：

{"reviews":[{"index":0,"verdict":"agree","severity":"ok","reason":"…","evidenceQuote":null}]}

- "index"：问题的编号，从 0 开始，与 `<judge_issues>` 一致。
- "verdict"：只能是 "agree"、"disagree"、"unsure"。
- "severity"：只能是 "ok"、"too-high"、"too-low"。
- "reason"：用中文书写，专有名词、缩写和公式可以保留原文。
- "evidenceQuote"：`<paper_data>` 里的原话（空白差别不要紧，其余字符必须一致），或 null。
