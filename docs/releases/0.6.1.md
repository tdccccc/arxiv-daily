# arXiv Daily 0.6.1

## Overview

This is an Obsidian-plugin-only release. It reworks the personal library's direction review dialog around a single clear next step, and replaces the Obsidian settings model field's two-control model picker with one type-ahead input that reliably lists every fetched model. The CLI (`arxiv-daily`) is republished as 0.6.1 with no behavior changes. The independently versioned DSH extension and Claude Code CLI integration are not part of this release. This release also raises the Obsidian plugin's minimum app version.

## Highlights

### Personal library: one clear next step in the direction review dialog

- The review dialog's default page no longer splits attention across tabs. It now leads with the current result, a short explanation, and a single primary action: **Update suggestions** when the indexed catalog has grown or changed since the last proposal, **Try again** after a read failure (with generation kept visible but disabled as a fallback, with an explanation), or **Done** when nothing new needs review.
- The **Add to research topics** bar now sits below the direction list instead of being split across tabs.
- Diagnostics, the library overview, and maintenance controls moved under **More options**; the overview gained an explicit **Back to review** action.
- Long direction text no longer renders in bold run-on styling, so it wraps normally and stays readable.
- Regenerating proposals only asks for confirmation when it would discard unreviewed directions or unsaved edits — routine regeneration no longer interrupts with a confirmation it doesn't need.

### Obsidian plugin: one type-ahead model field

- Fixed: in 0.6.0, **Get models** in Obsidian settings could show an empty suggestion list, or only the model already typed in the field. The suggestions were filtered by the field's current text.
- The model field is now a single type-ahead input. After **Get models**, every fetched model is offered as a suggestion, with the currently saved model listed first and marked "(current)". Typing filters the list (case-insensitive), and picking a suggestion saves it the same way typing does. You can still type any model name by hand, for example for providers that don't publish a model list.
- The fetched list is kept per endpoint (provider/base URL/API key). A list from another provider is never shown, and the list survives a settings redraw during the fetch.

### Obsidian minimum version raised to 1.5.7

- `AbstractInputSuggest`'s `getSuggestions` hook, which the new model field relies on, is only available starting Obsidian **1.5.7** (`@since 1.5.7` in `obsidian.d.ts`); the plugin's `minAppVersion` rises from `1.4.0` to `1.5.7` accordingly. Obsidian versions older than 1.5.7 will no longer offer this release as an update and will keep receiving 0.6.0 (`minAppVersion` 1.4.0) until they update Obsidian itself.

## Platform notes

- Unchanged from 0.6.0: the CLI's personal-library runtime is exercised on Linux (Node 20.19 and 22) only; the DSH extension is verified on Linux x64 only.

## Known issues

- Carried over from 0.6.0, unrelated to this release's changes: the one-off native backup read on macOS arm64 (cause unknown, not reproduced since), the CLI personal library being Linux-only so far, and the DSH extension's narrow (Linux x64, Web profile) coverage.

## Install / upgrade

### CLI

`arxiv-daily@0.6.1` is published with the rest of the release group, so versions stay in step. It has no behavior changes from 0.6.0, so upgrading is optional.

### Obsidian plugin

Update through Obsidian's Community plugins interface after the matching GitHub release is available. The release assets remain exactly `manifest.json`, `main.js`, and `styles.css`. No settings or data migration is required from 0.6.0. Obsidian must be at version 1.5.7 or newer to receive and run this update; older Obsidian installs continue to see 0.6.0 as their latest compatible version.

### DSH extension and Claude Code CLI plugin (separate, not published here)

Version independently of arXiv Daily and are not affected by this release.

## Compatibility

- **CLI package:** `arxiv-daily@0.6.1`, a version-only bump with no behavior changes from 0.6.0.
- **Node.js:** 20.19.0 or newer for the CLI and plugin; Node.js 22 is also supported.
- **Obsidian minimum version:** raised from `1.4.0` to `1.5.7`.
- **CLI config:** unchanged; remains `schema_version = 1`.
- **Personal library:** processing remains opt-in on both hosts; existing reports and notes are not automatically rewritten.
- **DSH extension and Claude Code CLI plugin:** version independently of arXiv Daily and are not affected by this release's version bump.

## For maintainers

- `versions.json` and `plugin/versions.json` now map `"0.6.0": "1.4.0"` (restoring 0.6.0's true shipped floor, which had been temporarily held at `1.5.7` on main only to satisfy `check-release-version.mjs`'s invariant that the *current* latest entry match the manifest's `minAppVersion` while 0.6.0 was still that latest entry) and `"0.6.1": "1.5.7"`. The checker only validates the entry for the version being released, so this release's sync is free to correct the superseded 0.6.0 entry without affecting validation.
- No dependency, CLI, or core package changes are included in this release; the diff since 0.6.0 is confined to the Obsidian plugin and its test/desktop-acceptance tooling.

The release gate covers dependency audits, release tools, architecture boundaries, lint, workspace type checking and tests, production builds, the Obsidian submission requirements check, build smoke, and CLI package installation smoke.
