# arXiv Daily 0.5.0

## Overview

This release opens the personal library to everyone: point arXiv Daily at a folder of PDFs and it builds a local, searchable catalog, finds similar papers, and can (with your say-so) let your own reading interests shape which papers show up in your daily report. Alongside it, this release closes out the setup-guide, settings, and reliability work from review, and brings automatic email delivery to macOS and Windows for the first time. The library workflow now centers on titles and abstracts, with reviewed directions stored inside research topics.

## Highlights

### Personal library and research directions (new)

- **Choose a folder, then review suggestions.** Personal library is the single setup area. Choosing a folder in settings automatically prepares its title-and-abstract index; the first preparation scans the folder when no valid previous scan exists. Preparation shows progress and can be cancelled, with Retry preparation available if the library is not ready. Later indexing reuses the saved catalog; after adding or removing PDFs, use Scan library and the existing indexing command to refresh it. Failed or cancelled folder scans do not continue into indexing.
- **Index titles and abstracts, not whole papers.** The index reads the first two PDF pages, extracts the title and a bounded abstract, then embeds that text. When no abstract marker can be found, it may use a bounded passage from the leading pages. PDFs without usable title or abstract text are reported as failures. Text outside the extracted title, abstract or bounded leading-page fallback is not indexed. Search results open the PDF, rather than jumping to a passage.
- **Search and discover directions from unrecognized PDFs too.** A successful arXiv lookup is not required: locally extracted titles and abstracts can support library search, similar-paper results and direction proposals. Failed arXiv metadata lookups do not exclude otherwise readable PDFs from indexing.
- **Existing development indexes need a rebuild.** Old full-text chunks are not reused as title-and-abstract evidence. After a completed conversion, papers that failed conversion are reported and excluded from the new searchable index; retrying can restore them. Current title-and-abstract records can be reused when the file, model and extraction rules are unchanged. Search data is derived locally and can be rebuilt.
- **Research topics hold a list of directions.** Existing topic descriptions migrate into direction text. Library analysis can suggest topics and directions, explain existing coverage and show supporting papers. Review, edit, preview and accept selected suggestions into research settings; accepting part of a proposal leaves the rest available and respects later edits or deletions. Suggestions affect daily reports only after acceptance.
- **Review suggestions generates on first use.** When the prepared library has no saved proposal, this button asks for any required model authorization and generates suggestions in the review dialog. Existing proposals open without being replaced. Closing the review cancels its generation; cancelling authorization leaves the library available for another attempt. The larger dialog gives proposals and evidence room to breathe, with scrolling and wrapping controls in smaller windows. Scan library remains available for refreshing the collection.
- **Daily reports explain matched directions.** Filtering uses the directions within each topic. The most relevant matching papers are kept before summarization, with a configurable daily limit (default 20). Reports distinguish papers omitted by the limit from directions with no matching paper. Personal-novelty comparison remains inactive pending a new comparison basis.
- The personal library remains optional; the settings introduction explains the setup sequence and the research-direction review entry stays discoverable. The older PDF sidecar setting is no longer offered for this title-and-abstract indexing path.

### Privacy and network

- **Local embedding is the default.** On first use it downloads approximately **130 MB** of model files from Hugging Face, then caches them for local processing. A blocked download is reported as a network problem. There is currently no mirror setting. Preparation shows model-file loading progress without mistaking cached reads for a new download. Time depends on the number of PDFs, extraction quality, the device and any first-time network work; old full-text timings do not describe this new index.
- **Remote embedding and direction generation ask for authorization.** Remote embedding sends extracted title-and-abstract chunks to the configured embedding endpoint; direction generation sends title-and-abstract evidence to the configured language-model endpoint. Full PDF bodies are not embedded. Endpoints are disclosed, authorization can be revoked, and endpoint/scope changes invalidate it. Stored legacy authorization depth tokens remain compatible; the visible disclosure describes the narrower current content.
- **Scanning calls arXiv's public API.** Paper IDs or candidate titles may be sent to arXiv for identification and metadata. This has no separate consent prompt and is distinct from model authorization. First-time preparation includes this scan; arXiv network failures can leave files unrecognized without making their local title/abstract unusable.
- Switching embedding models or vector dimensions rebuilds the index in separate files before promoting the new manifest. Cancellation or a failed promotion preserves the previous index; no manual deletion is required. Inconsistent cached paper records are detected and re-extracted during preparation. Failed or unfinished preparation remains visibly retryable.

### Setup and onboarding

- **The setup guide now finishes for good** — Once every milestone (ready to run, first report generated, daily schedule on) has been true at the same time, the guide disappears permanently and does not come back, even if the schedule is later turned off or the configuration breaks again. If something does go wrong afterward, a compact "Configuration needs attention" card explains why, instead of nothing at all. Existing configured users are detected on upgrade and will not see the guide reappear.
- **More trustworthy guide behavior** — Guide buttons on Obsidian 1.13+ reliably scroll to and focus the right field; new topics can no longer get a duplicate tag that silently stalls the guide; the guide includes a step for turning on the daily schedule and does not report "done" until that step is on; the first report step generates using the most recently announced arXiv day, so it also works on weekends or before the day's listing is published; and manual runs now refresh any dashboard views left open.

### Settings

- **Topic cards focus on names and directions.** Machine tags are hidden from the settings editor and managed automatically; existing custom tags are preserved. Long topic names have more room.
- Editing continues to save reliably: duplicate categories are rejected instead of silently dropping a row, failed topic/category saves roll back and report the error, service and path fields commit at the appropriate editing boundary, folder/sender fields save correctly when editing ends on Obsidian 1.13+, the legacy Thinking-mode toggle stays in step with the effort setting, and the model field now accepts free text with "Get models" offered as suggestions rather than overwriting it.
- Research settings now support one-line directions within each topic and a shared daily paper limit.

### Reliability of daily runs and email

- **Crash-interrupted runs retry automatically** — A run left marked "running" by a crash used to be recovered as permanently failed and never retried. It now retries automatically instead.
- **A stricter filter format is accepted** — A model's filter answer wrapped in a single code fence is now accepted instead of failing the day outright.
- Paper Index failures encountered while filtering are now treated as retryable instead of permanent. Paper-note frontmatter stays valid YAML for any topic tag, and refreshing frontmatter keeps user-added properties.
- Multiple Plugin/CLI processes sharing the same Vault on one machine now coordinate daily runs and Paper Index updates through a shared local lock with crash recovery, so concurrent runs no longer race or lose updates; the same lock also protects plugin startup cleanup.
- **Automatic email delivery now works on macOS and Windows** — automatic email previously depended on a Linux-only filesystem capability and silently could not run elsewhere; the CLI and plugin now bundle a native private-storage component for this, verified in CI across six OS/architecture targets (Linux, macOS, and Windows, each x64 and arm64). Real-desktop verification inside a running Obsidian session was performed on Linux; macOS and Windows are covered by the native CI matrix rather than a real desktop session. When automatic email genuinely cannot run, the plugin and CLI now say so plainly instead of only logging it while a manual test send still reports success.
- LLM requests now send only the parameters a given provider actually supports, instead of a leftover SDK-specific wrapper; the official Anthropic API also gets its own native request path so a configured thinking effort reaches Anthropic's documented extended-thinking controls correctly.

### CLI

- Cron installation now correctly escapes executable paths containing spaces, quotes, other shell-special characters, or `%`; paths that cannot be represented safely are rejected before anything is written to the crontab.
- Invalid or inverted recurring run-time windows are rejected instead of silently installing a broken schedule or overwriting an existing crontab entry.
- Async CLI subcommand failures now consistently return the correct exit code with a redacted error message, and signal handlers clean up only after the operation actually finishes.
- `arxiv-daily init` now writes `config.toml` with owner-only permissions and creates new config directories as owner-only, since the file holds LLM and email credentials. Existing installs are unaffected until `init` is run again — plain config reads do not change permissions retroactively. (Verified on POSIX permissions; Windows ACL behavior was not separately verified.)

### Security and dependencies

- Abstract and author parsing avoid costly backtracking on long whitespace input, and nested settings updates reject prototype-property paths.
- The email relay now rejects non-object JSON (including `null` and arrays) at its request boundary with a clear client error, without touching the delivery service or state.
- Vulnerable relay tooling was upgraded and root tooling dependencies were audited and secured.

## Platform notes

- Library preparation, suggestion generation, acceptance, persistence and review-window operation were manually verified by the user on Linux, including recovery of an existing development library. macOS and Windows Obsidian sessions have not been manually verified; the native storage component has separate CI coverage across six OS/architecture targets.
- The Obsidian plugin remains desktop-only, so the personal library is not available on mobile.

## Install / upgrade

### CLI

```bash
npm install -g arxiv-daily@0.5.0
# or:
arxiv-daily update
```

If you rely on automatic email and previously saw it silently do nothing on macOS or Windows, reinstalling picks up the new native storage component automatically.

### Obsidian plugin

Update through Obsidian's Community plugins interface after the matching GitHub release is available. The release assets remain exactly `manifest.json`, `main.js`, and `styles.css`.

Library preparation starts after choosing a folder or explicitly retrying/rebuilding it. Opening Obsidian does not start preparation automatically.

## Compatibility

- **CLI package:** `arxiv-daily@0.5.0` after publication.
- **Node.js:** 20.19.0 or newer; Node.js 22 is also supported.
- **Obsidian minimum version:** unchanged at `1.4.0`.
- **CLI config:** remains `schema_version = 1`, and supports direction lists and `max_daily_papers`. Existing topic descriptions migrate into directions; no manual configuration migration is required.
- **Plugin setup:** the new `onboarding.guideCompleted` flag defaults safely and is detected for already-configured users on load.
- **Personal library:** processing remains opt-in. Existing reports and notes are not automatically rewritten. Direction-based filtering and the default daily paper limit also apply to ordinary reports without a connected library.
- **CLI config file permissions:** existing `~/.config/arxiv-daily/config.toml` files keep their current permissions until `arxiv-daily init` is run again, which then writes them owner-only.
- **Paper Index:** reads existing schemas 1–5 and writes schema 5; no manual migration is required.
- **Delivery state:** remains schema 1 for older-reader compatibility; private sidecars carry the stronger claim generation.
- **Existing configs, reports and paper notes:** remain supported. Existing development full-text library indexes must be rebuilt for the title-and-abstract scope.
- **Older development suggestions:** valid retired v2–v5 proposals are distinguished from corruption. Use Regenerate suggestions to create current-format suggestions; the original primary and backup are archived first. A newly appearing current draft is never overwritten by that recovery action.

## For maintainers

The release gate covers dependency audits, release tools, architecture boundaries, lint, Node 20.19/22 compatibility, workspace type checking and tests, production builds, the Obsidian submission requirements check, build smoke, and CLI package installation smoke. Native private-storage components are now built and verified in CI across Linux, macOS, and Windows on both x64 and arm64, with release builds failing if any of the six platform artifacts is missing. The email relay and VS Code companion retain independent lockfiles and workflows; relay verification performs a Wrangler dry-run only and does not deploy or read production credentials.
