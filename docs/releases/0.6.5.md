# arXiv Daily 0.6.5

## Overview

This is a maintenance release. It makes daily generation more tolerant of imperfect model answers, lets you regenerate a report you deleted, and stops several things from failing silently.

The Obsidian plugin and the CLI (including the standalone workbench, `arxiv-daily ui`) both change. Email delivery is unchanged.

## Highlights

### Daily reports

- **A deleted report can be generated again.** If you delete a day's report, any manual run for that date now writes it again: Run today, the run commands and the calendar in Obsidian, `arxiv-daily run --today` / `--date`, and "Regenerate report" in the workbench. Scheduled runs, Run all pending and Retry failed never bring a deleted report back. An existing report is never overwritten.
- **A badly formatted model answer is asked again instead of failing the day.** A filter answer that breaks the expected format is re-asked once with the broken rule spelled out. The step that picks papers for detailed notes does the same, and if it still fails the run says that paper notes were skipped instead of silently writing none.
- **Generation runs a few papers at a time.** Summaries and paper notes are generated at most three at once. The CLI can change this with `generation_concurrency` (1 to 8) under `[advanced]`.
- **Papers held back by the daily limit stay out of your paper list.** Only papers that reach the report are added to the index, so a paper cut by the limit no longer appears in the Dashboard or the workbench inbox.
- **Papers a provider refuses are recorded as refused.** They used to be recorded as skipped by the model.
- **Topics are checked before anything is fetched**, and fetch progress now counts papers that have actually finished.

### Personal library

- **Failed arXiv lookups are retried.** If arXiv was unreachable while your folder was scanned, building the index again now retries those papers. The completion message and the workbench library page say so.

### CLI and workbench

- **A setting with the wrong type is now an error.** A known key in `config.toml` whose value has the wrong type (for example `thinking_mode = "yes"`) used to be ignored. The CLI now stops and names the key, the expected type and the value it found. See "Upgrade notes".
- **`init` is stricter and tests more.** It asks for a real research direction instead of accepting its placeholder, defaults thinking mode to what the chosen provider preset uses, and sends one real chat request so a provider that rejects your settings is caught in the wizard.
- **Model listing works with Anthropic's own API**, in plugin settings, `init` and the workbench.
- **The workbench notices runs it did not start.** An idle workbench page now shows a run the server started on its schedule, and refreshes the list and calendar when it finishes.

## Upgrade notes

- **Check `config.toml` if the CLI stops with "invalid ... expected ...".** The message names the key to fix. A `request_delay_ms` below 3000 is still raised to 3000, now with a warning.
- **A cron job that runs `arxiv-daily run --today` counts as a manual run.** If you delete today's report and the job runs again the same day, the report is written again. `schedule install` writes this kind of entry.
- **Moving the daily folder makes recent completed dates look deleted**, so a manual run for one of them regenerates its report in the new place.
- **Older versions do not know about a regeneration in progress.** If 0.6.4 or earlier writes the run state while 0.6.5 is regenerating a deleted report, the marker that protects that date is dropped. Avoid running two versions against the same folder at the same time.

## Known issues

- A regenerated report is filtered from scratch. When several papers tie at the daily limit, the new report may pick a different one; a paper that dropped out keeps its entry and note from the first run.
- A date on which arXiv announced nothing (for example after a holiday) is retried and then marked failed instead of being recognised as empty. This predates this release.
- Carried over from 0.6.4: the grey comment line on papers that fell back to their abstract, no direct way from a report to a paper's reading page without a paper note, Obsidian's hosted review warning about rebuilding `main.js`, buffered streaming in Obsidian, quiet-period cleanup not removing old model-specific paper files, existing `1970-01-01` dashboard seen dates, and the 0.6.0 platform caveats.

## Install / upgrade

### CLI

```bash
npm install -g arxiv-daily@0.6.5
```

Or run `arxiv-daily update`.

### Obsidian plugin

Update through Obsidian's Community plugins interface after the matching GitHub release is available. The release assets remain exactly `manifest.json`, `main.js`, and `styles.css`. No settings or data migration is required from 0.6.4.

## Compatibility

- **CLI package:** `arxiv-daily@0.6.5`.
- **Node.js:** 20.19.0 or newer for the CLI and plugin; Node.js 22 is also supported.
- **Obsidian minimum version:** unchanged at `1.5.7`.
- **CLI config:** remains `schema_version = 1`; wrong value types are now rejected (see "Upgrade notes").
- **Plugin data:** `data.json` and the paper index keep their schemas. Run state gains an optional `rerunOf` field that older versions ignore. Filter checkpoints gain an optional list of refused papers; older documents still load.

## For maintainers

- Dependencies: ESLint 10, `@types/node` 26, and patch updates to jszip and linkedom (both in the CLI bundle). pako stays at 2.2.0.
- The acceptance exploration test that failed once on main because two timers landed on the same instant now decides which limit applies before the call starts.
- Before this release the candidate was exercised with a real model: a daily report was generated, skipped when present and regenerated after deletion with the CLI, and a model operated both the workbench and Obsidian through the full exploration task set.

The release gate covers dependency audits, release tools, architecture boundaries, lint, workspace type checking and tests, production builds, the Obsidian submission requirements check, build smoke, and CLI package installation smoke.
