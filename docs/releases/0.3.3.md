## Overview

arXiv Daily 0.3.3 introduces stable paper identity (`source:id` keys), a source-adapter boundary for future multi-source work, and optional email digests after a completed daily report. Digests support **Send yourself** (your Resend key) and **Official delivery (Beta)** (shared free path with a small daily limit). Settings copy is rewritten for end users, and scientific mail rendering softens TeX for clients without MathJax.

## Highlights

- **Paper identity (schema 4).** Papers are keyed as `source:externalId` (for example `arxiv:2606.12345`). Existing vaults read old indexes and upgrade on write; short disk stems stay stable.
- **Source adapter boundary.** Discovery and full-text fetch go through a `SourceAdapter` so arXiv remains the first source without baking arXiv-only IDs into every layer.
- **Email digests (optional).** After a successful daily run, a mobile-readable HTML/text digest can be emailed. Failures never fail report generation.
- **Dual delivery modes.** **Send yourself** (default): your Resend API key. **Official delivery (Beta)**: verify email once; project sends with a small shared daily quota.
- **User-facing settings.** Labels and notices avoid developer jargon (verification code, folders, capacity limits).
- **Official delivery capacity.** Public Beta quota is intentionally low (a few messages per verified inbox per UTC day; tests count). Heavy use should switch to Send yourself.

## Paper identity and sources

- Paper Index schema version **4** with `paperKey`, `source`, `externalId`, and retained `arxivId` for arXiv papers.
- Read compatibility for older bare arXiv IDs; write path upgrades to composite keys.
- Pipeline listing/content paths use the arXiv source adapter; local HTML/TeX caches remain via the existing content fetcher.

## Email delivery

- Digest is a projection of the completed daily result (not raw vault Markdown).
- Zero-day runs can still send a short “no relevant papers” digest when auto-send is on.
- Deterministic TeX softening for mail (`emailProse`); vault notes keep full scientific Markdown.
- **Send test** does not mark the calendar day as formally delivered.
- Cross-mode skip: once a date is delivered to a recipient, that date is not resent by default (either mode).
- Official delivery Worker: magic-link verify, device token, per-inbox daily quota, deliver idempotency (Durable Object gate), rate limits on verify-start.
- Default Official base URL: `https://mail.arxiv-daily.top`.

## Settings and UX

- Email guide steps for both modes; Official delivery states capacity limits clearly.
- Secrets (LLM key, Resend key, verification code) saved on device and hidden after save.
- Section polish and sentence-case lint cleanup for Community Plugin review budget.

## Data compatibility

- Existing daily reports, detail notes, command IDs, and output paths remain readable.
- Paper Index upgrades to schema 4 on the next write; no manual migration required.
- New optional settings under `email`; defaults keep auto-send off and mode `self`.
- New vault state file for delivery bookkeeping when email is used (`delivery-state` under the arXiv Daily index).

## Security and privacy

- **Send yourself:** Resend key stays on the device; outbound mail goes only to the configured provider.
- **Official delivery:** plugin sends digest content to the project relay after verification; Resend project keys stay on the server; verification codes are treated as secrets.
- Saved API keys and verification codes remain plaintext in Obsidian plugin settings storage for compatibility (same model as prior releases).
- No client-side telemetry.
- Official delivery is rate-limited and quota-limited; open CORS `*` is not used for credentialed deliver.

## Install

Download these three assets and copy them to:

```text
<your-vault>/.obsidian/plugins/arxiv-daily/
```

- `manifest.json`
- `main.js`
- `styles.css`

Restart Obsidian, then enable **arXiv Daily** under **Settings → Community plugins**.

If you already use Community Plugins or BRAT, update to **0.3.3** and reload the plugin.

## Breaking changes

There are no command-ID or vault Markdown format breaks. Existing users can upgrade in place.

Behavioral notes:

- Paper Index internal keys become `arxiv:…` composite keys after upgrade (display and note paths remain short-stem friendly).
- Optional email is off by default; enabling Official delivery is subject to shared Beta capacity.
