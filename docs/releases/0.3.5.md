# arXiv Daily 0.3.5

## Overview

CLI-focused release: **thinking mode is configured in `init` (default on)**, and a new **`arxiv-daily update`** command simplifies upgrading the global npm install. Plugin behavior is unchanged aside from shared version metadata.

## Highlights

- **Thinking in `init`** — After you pick a model, the wizard asks:
  - Enable thinking mode? (**default: Yes**)
  - Reasoning effort: `low` / `medium` / **`high` (default)** when thinking is on  
  Values are written to `config.toml` as `thinking_mode` and `reasoning_effort` (no longer only the provider preset flag).
- **`arxiv-daily update`** — Check npm for a newer CLI and optionally run `npm install -g arxiv-daily@…`. Does not modify your config or vault.
- **Version in `help`** — `arxiv-daily help` prints the embedded package version.

## Install / upgrade

```bash
npm install -g arxiv-daily@0.3.5
# or, if you already have 0.3.4+ with the update command:
arxiv-daily update
# check only:
arxiv-daily update --check
# non-interactive:
arxiv-daily update --yes
```

Fresh install:

```bash
npm install -g arxiv-daily
arxiv-daily init
arxiv-daily run --today
```

Uninstall (config/vault kept):

```bash
npm uninstall -g arxiv-daily
```

## CLI: thinking settings

Written under `[llm]` in `~/.config/arxiv-daily/config.toml`:

```toml
thinking_mode = true
reasoning_effort = "high"   # low | medium | high
```

- Prefer **on** for better filtering/summaries (more tokens and latency).  
- Existing configs keep their current values until you re-run `init` or edit the file.  
- If you used 0.3.4 `init` with OpenAI/Zhipu/Custom, you may still have `thinking_mode = false` from the old preset-based write — set it to `true` manually or re-run `init`.

## CLI: `update`

| Flag | Meaning |
|---|---|
| *(none)* | Show current vs latest; prompt to install globally |
| `--check` | Only report versions; never install |
| `--yes` / `-y` | Install without confirmation |

- Current version is embedded at build time.  
- Latest is read from the npm registry.  
- Install uses `npm install -g arxiv-daily@<latest>`.  
- Non-TTY sessions need `--yes` (or use `--check` / run `npm install -g` yourself).  
- **Does not** load or change `config.toml`.

## Commands (full surface)

```text
arxiv-daily init
arxiv-daily update [--check] [--yes]
arxiv-daily run --today
arxiv-daily run --date YYYY-MM-DD
arxiv-daily run --id ARXIV_ID [--date YYYY-MM-DD]
arxiv-daily email test|status|verify-start
arxiv-daily schedule show|install|uninstall
arxiv-daily data export --out PATH.zip
arxiv-daily data import PATH.zip [--yes]
arxiv-daily help
```

## Compatibility

- **npm package:** `arxiv-daily@0.3.5` (bin `arxiv-daily`).  
- **Config format:** still `schema_version = 1` at the bottom of the file.  
- **Plugin:** version bump only; no intentional plugin behavior change.  
- Configs from 0.3.3/0.3.4 remain valid.

## Upgrade notes from 0.3.4

1. `npm install -g arxiv-daily@0.3.5` (or `arxiv-daily update` after this version is installed once).  
2. Optionally enable thinking in `config.toml` if it was off.  
3. No vault migration.
