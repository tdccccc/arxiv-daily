# arXiv Daily 0.6.0

## Overview

This release brings the local reading workbench to the published `arxiv-daily` CLI package for the first time: `arxiv-daily ui` opens a browser-based reader with settings, calendar, search, and a personal-library workflow, with no Obsidian required. The CLI also gains terminal commands for the personal library (connect, index, propose and accept research directions) that previously existed only in the Obsidian plugin. Separately, an independent DeepSeek Harness (DSH) extension embeds the same workbench inside DSH; it ships and versions on its own and is not part of this npm/GitHub release. On the Obsidian side, this release closes out three issues Obsidian's hosted 0.5.0 community review raised against the plugin submission, and patches two dependency advisories.

## Highlights

### Standalone reading workbench (CLI, new)

- **`arxiv-daily ui [--port PORT] [--no-open]`** starts a local, loopback-only (`127.0.0.1`) HTTP server and opens a browser reader. It works with or without existing configuration: with no configuration, it opens first-run setup (save directory, model, arXiv categories, topics and directions) automatically.
- A left sidebar holds a calendar (day cells show paper counts and run status) and search/topic/reading filters; the right side lists indexed papers and opens daily reports or paper notes. Reading Markdown — including tables, code, images and math — never edits the original file or calls a model.
- Back/forward navigation stays within the current workbench session (filters, anchors and scroll position are restored); it does not persist across restarts.
- Settings mirror the Obsidian 1.13+ section layout and controls (model, categories, topics, detail policy, output/schedule, personal library, email, advanced) and **save automatically** as you edit; closing waits for pending saves. A saved API key can be explicitly revealed (Show) or hidden again.
- Generating a report or a paper note from the workbench reuses the same daily/manual pipeline, including configured email delivery, and shows progress and cancellation.
- Reading status (unmarked/to-read/read), favorites, and the reading footer (token counts, duration, generation timestamp) are shared with the Obsidian Dashboard through the same Paper Index.

Once `arxiv-daily@0.6.0` is published, `npm install -g arxiv-daily` (or `npx arxiv-daily@latest ui`) includes this workbench — a source build is no longer required to try it.

### Personal library commands for the CLI (new)

- New subcommands: `library connect`, `status`, `prepare`, `scan`, `index`, `propose`, `directions`, `confirm`, `review`, `search`, `authorize`, `revoke`. These mirror the Obsidian plugin's personal-library workflow (introduced in 0.5.0) so CLI-only setups can build a local title/abstract index from a PDF folder, generate direction proposals, and accept them into ordinary research topics — all from the terminal.
- In the workbench itself, **Personal library** browses and searches the indexed catalog and opens local PDFs (up to 25 MiB); **Review directions** shows proposals with representative evidence, lets you edit, rename, move or remove candidates, preview matches, and explicitly accept selected directions. Accepted directions only affect report filtering after acceptance.
- `library prepare` installs pinned, optional PDF-parsing and local-embedding runtime components into a configured cache on first use (the same local embedding model used by the Obsidian plugin). Remote embedding skips that local component but requires the same disclosed title/abstract authorization as before.
- This CLI library runtime has been exercised on Linux (Node 20.19 and 22) only so far; Windows and macOS smoke checks are still outstanding (see Known issues).

### DeepSeek Harness (DSH) extension — separate product

- `dsh-arxiv-daily` is a new, independently versioned extension (currently **0.1.18**) that embeds the same reading workbench as a fixed sidebar entry in DSH. It is governed and released on its own schedule and is **not** part of this arXiv Daily 0.6.0 release — there is no npm package for it yet; it is built and installed as a local `.tgz` from source. See [extensions/dsh-arxiv-daily/README.md](../../extensions/dsh-arxiv-daily/README.md) for build and install/upgrade steps.
- It reuses the CLI's local configuration (`~/.config/arxiv-daily/config.toml` or `%APPDATA%\arxiv-daily\config.toml`), so installing or upgrading it does not require re-running `init` if you already use the CLI. It still writes the same Markdown daily reports and paper notes as the Obsidian plugin when pointed at the same output folder, but configuration and secrets are not shared with the plugin.
- Verified so far against a local DSH Host on Linux x64 only; cross-platform packages and Electron desktop visual behavior have not been separately verified.

### Claude Code CLI integration — separate, optional

- An existing, independently versioned Claude Code plugin ([extensions/claude-code-arxiv-daily](../../extensions/claude-code-arxiv-daily/README.md)) can open the same workbench from inside Claude Code for conversational assistance. It calls arXiv Daily's own configured model endpoint, not Claude's conversation model, and is likewise not part of this release's versioning.

### Obsidian plugin: directory review follow-ups

Obsidian's hosted review of the 0.5.0 submission raised findings that risked the plugin's Community-directory listing; this release addresses the three that needed code changes. None of these change plugin behavior for an already-installed user.

- **`authorUrl` now points at the author, not the plugin repository** (`https://github.com/tdccccc`), matching Obsidian's submission guidelines that `authorUrl` identify the author.
- **The build no longer requires a C++ toolchain for non-release builds.** Obsidian's hosted build verification has no CMake/compiler available; `npm run build` now detects a missing CMake and falls back to building without an embedded native storage component (with a printed warning) instead of failing outright. Official release builds (used for the published plugin and CLI) are unaffected and still require the full verified native build.
- **A review-scanner-parity lint pass was added** (`npm run lint:review`, plus a small CSS check) that reproduces the rule set Obsidian's hosted reviewer uses across the whole production TypeScript tree (not just the plugin), and the warnings it found — unsafe `any` leaks, deprecated APIs, stray type assertions, a couple of `!important`/`:has()` uses in `plugin/styles.css`, and similar — were cleaned up. This is internal tooling and code hygiene; it is not part of the required release gate (`npm run lint`) and does not change behavior.

### Security and dependencies

- Patched two new advisories flagged by `npm audit --audit-level=moderate`: `source-map-js` (high, GHSA-68fv-2mgg-jv7q — pulled in transitively by `vite`/`postcss` dev tooling, pinned to `^1.2.2`) and `smol-toml` (moderate, GHSA-r4xh-jqrq-34v2 — raised to `^1.9.0`). `source-map-js` is build-time only and was never part of a shipped bundle. **`smol-toml` is bundled into the published CLI binary**, where it parses `config.toml` (and library/connection TOML) at runtime; 0.5.0 and earlier CLI releases shipped the vulnerable `1.7.1`, so upgrading to 0.6.0 is recommended for anyone using the CLI.
- `katex`'s existing low-severity prototype-pollution advisory (GHSA-238p-pmpm-9mq7) remains unaddressed — fixing it needs a breaking upgrade to 0.19 — and stays below the `moderate` audit threshold this release gate enforces.

## Platform notes

- The Obsidian plugin's platform coverage is unchanged from 0.5.0.
- The CLI's personal-library runtime (local PDF parsing and embedding) has been exercised on Linux (Node 20.19 and 22) only; Windows and macOS are not yet smoke-tested.
- The DSH extension has been verified against a local DSH Host on Linux x64 only.

## Known issues

- **One-off native backup read on macOS arm64 (cause unknown, carried over from 0.5.0).** A single CI run of the native private-storage component's atomic-replace test, on macOS arm64, once read back 3 NUL bytes from a hard-link backup instead of the expected prior contents; reruns and a further 2,000-cycle diagnostics pass across all six CI platforms have not reproduced it. Nothing in this release touches that component's logic; diagnostics remain in CI so a recurrence leaves evidence.
- **CLI personal library is Linux-only so far.** `arxiv-daily library …` and the workbench's local embedding/PDF parsing have real test coverage on Linux; Windows and macOS have not had platform smoke checks yet.
- **DSH extension coverage is narrow.** Only a local Linux x64 build against DSH's Web profile has been exercised; Electron desktop visual behavior and other platforms are unverified.

## Install / upgrade

### CLI

```bash
npm install -g arxiv-daily@0.6.0
# or:
arxiv-daily update
```

This is the first CLI release that includes the local reading workbench (`arxiv-daily ui`) and the `arxiv-daily library …` commands; no separate install step is needed.

### Obsidian plugin

Update through Obsidian's Community plugins interface after the matching GitHub release is available. The release assets remain exactly `manifest.json`, `main.js`, and `styles.css`. No settings or data migration is required from 0.5.0.

### DSH extension (separate, not published here)

Not distributed with this release. Build and install it from source following [extensions/dsh-arxiv-daily/README.md](../../extensions/dsh-arxiv-daily/README.md); it reuses your existing CLI configuration and Markdown output.

## Compatibility

- **CLI package:** `arxiv-daily@0.6.0` after publication.
- **Node.js:** 20.19.0 or newer for the CLI and plugin; Node.js 22 is also supported. (The separate DSH extension requires Node.js 22.19+ to build.)
- **Obsidian minimum version:** unchanged at `1.4.0`.
- **CLI config:** remains `schema_version = 1`. Personal-library settings (connection, authorization, accepted directions and receipts) are stored in the same CLI TOML and are not automatically synchronized with Obsidian's settings.
- **Personal library:** processing remains opt-in on both hosts; existing reports and notes are not automatically rewritten.
- **DSH extension and Claude Code CLI plugin:** version independently of arXiv Daily and are not affected by this release's version bump.

## For maintainers

- `product-units.json` gained a new `independent-extension` unit for `dsh-research-plugin`, with its own CI workflow (`.github/workflows/dsh-plugin.yml`) gated on the paths it actually depends on.
- `docs/release.md` was reordered to prepare, verify, commit and push a release branch, tag and publish from it, and only then open the PR into `main` — closing the gap that got 0.5.0 briefly delisted from Obsidian's Community directory between its manifest bump and its published release. `scripts/check-published-manifest.mjs` now enforces this in CI on every push to and PR against `main`.
- CI's DSH plugin workflow installs `pnpm` before running DSH integration tests; the release checker now distinguishes legitimate nested `node_modules` dependencies from unknown workspace roots in `package-lock.json`.
- The email relay's internal lint cleanup (type-assertion and loop warnings) is behavior-preserving; it retains its own independent lockfile and dry-run-only CI verification.

The release gate covers dependency audits, release tools, architecture boundaries, lint, workspace type checking and tests, production builds, the Obsidian submission requirements check, build smoke, and CLI package installation smoke.
