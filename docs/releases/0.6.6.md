# arXiv Daily 0.6.6

## Overview

This is a bug-fix release. Daily reports no longer fail when your model service does not accept one of the optional settings arXiv Daily sends with each request.

The Obsidian plugin and the CLI (including the standalone workbench, `arxiv-daily ui`) both change. Email delivery is unchanged.

## Fixes

- **A model service that rejects an optional setting no longer fails the day.** A provider preset adds settings such as thinking mode, reasoning effort or temperature to each request. If the base URL points at a different service, for example the DeepSeek preset with an OpenAI-style endpoint, that service could answer "Unknown parameter: 'thinking'" and every date was marked failed. arXiv Daily now sends the request again without the setting the service named, leaves it out for the rest of the run, and writes a warning to the log. "Test connection" in the settings and `init` behave the same way, so they pass whenever a report would. Anthropic's own API is not affected.

## Upgrade notes

- **Dates that failed because of this error stay failed until you run them again.** Use the calendar in Obsidian, "Retry failed", or `arxiv-daily run --date YYYY-MM-DD`.
- **Picking the provider that matches your service is still best.** When a setting is left out, the model runs with that service's default, for example without thinking mode. The log says which setting was dropped.

## Known issues

- Carried over from 0.6.5: a regenerated report is filtered from scratch, so with ties at the daily limit it may pick a different paper; a date on which arXiv announced nothing is retried and then marked failed instead of being recognised as empty; and the items listed under 0.6.4.

## Install / upgrade

### CLI

```bash
npm install -g arxiv-daily@0.6.6
```

Or run `arxiv-daily update`.

### Obsidian plugin

Update through Obsidian's Community plugins interface after the matching GitHub release is available. The release assets remain exactly `manifest.json`, `main.js`, and `styles.css`. No settings or data migration is required from 0.6.5.

## Compatibility

- **CLI package:** `arxiv-daily@0.6.6`.
- **Node.js:** 20.19.0 or newer for the CLI and plugin; Node.js 22 is also supported.
- **Obsidian minimum version:** unchanged at `1.5.7`.
- **CLI config:** unchanged, `schema_version = 1`.
- **Plugin data:** unchanged.

## For maintainers

- The fallback lives in the LLM client (`packages/core/src/llm/client.ts`). The earlier `stream_options` fallback now goes through the same path and stays silent.

The release gate covers dependency audits, release tools, architecture boundaries, lint, workspace type checking and tests, production builds, the Obsidian submission requirements check, build smoke, and CLI package installation smoke.
