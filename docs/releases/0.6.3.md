# arXiv Daily 0.6.3

## Overview

This release is mostly about making daily reports more trustworthy and making failures easier to recover from. It adds a way to see when the daily filter had to judge papers from their titles alone, a nudge to update library direction suggestions when you add papers, and many fixes to email delivery, interrupted runs and damaged data files. It follows two deep reviews of the product and a round of testing in real Obsidian and the real workbench.

One earlier idea did not ship: the personal "novelty" comparison for daily reports was built, tried on a real library and withdrawn (see below).

All three hosts change: the Obsidian plugin, the CLI (including the standalone workbench, `arxiv-daily ui`), and email delivery. The independently versioned DSH extension ships alongside as `dsh-arxiv-daily` 0.1.19.

## Highlights

### Daily reports: more honest and more reliable

- **Personal novelty is withdrawn.** The comparison against similar papers in your library is gone from daily reports. The papers it compared against were chosen by text similarity, so there was no way to tell whether they were comparisons you cared about. Existing reports stay readable and are not rewritten. The personal-library consent wording is back to its earlier text.
- **Title-only filtering is now visible.** When arXiv throttles abstract requests, some papers used to be filtered on their titles alone with no sign of it. Now missing abstracts are first filled from each paper's arXiv abstract page. If some papers still had to be judged on the title only, the report header says how many, and the same count appears in the run history, the CLI run line and the Obsidian run notices. The run still counts as completed.
- **Filter decisions are recorded.** After each completed run, the filter's decision for every candidate (including rejected papers) is kept per date in your data, so you can later check what the filter missed. Old dates are pruned. This works in the plugin and the CLI; a Chinese guide for measuring filter quality is in `scripts/quality-eval/`.
- **Summaries survive more model and source problems.**
  - LaTeX that the model writes with single backslashes no longer makes a summary fall back to the English abstract.
  - A reply the provider cut off, or a stream that simply stops, is no longer accepted as a finished summary. It is retried, and the last attempt falls back.
  - One paper refused by a provider's content filter no longer fails the whole day. That paper gets a fallback entry.
  - If the full text can't be fetched, the summary is written from the abstract rather than a placeholder.
  - Source formulas such as `\frac{1}{3}` survive the fallback, and malformed TeX can no longer freeze the app. Untrusted paper text can't turn into remote images or embedded notes in a report.
- **Long arXiv listing days are read in full.** A day with more than 2000 entries is no longer cut off at the first page.
- **Real LLM streaming (CLI and workbench).** Streamed replies are now read as they arrive, so the 120 second idle timeout and the output cap act on the live connection. Requests are not blindly re-sent after a timeout. Obsidian keeps its existing buffered path.

### Personal library

- **Library change nudge.** After indexing, the Obsidian plugin shows one notice when three or more new papers are not reflected in your direction suggestions, with an **Update direction suggestions** button. Updating sends only the new papers plus your existing directions and tells you how many of them your directions already cover. It falls back to a full scan when there is no baseline. The old **Update suggestions** button is now **Recheck coverage**. The workbench and `arxiv-daily library propose --new` do the same.
- **New PDFs are picked up.** Indexing an already scanned library now notices PDFs you added (by a local listing, no network), and looks up arXiv metadata only for papers not yet in the catalog. `arxiv-daily library index` also scans a never-scanned library.
- **Library recovery.**
  - A paper's own arXiv id is used when identifying a PDF, not an id cited in its abstract. Files that were misidentified are re-identified on the next scan.
  - Two identical PDFs in different folders no longer make indexing fail forever.
  - File names the catalog can't hold (for example containing backslashes) are skipped and reported instead of failing the scan.
  - PDFs whose arXiv title lookup couldn't be made are asked about again on the next scan.
  - Interrupted indexing reuses finished paper documents instead of starting over.
  - Pasting a long abstract into library search no longer throws, and library search is faster.
- **Quiet-period index cleanup.** Obsolete search generations can be reclaimed on request: `arxiv-daily library maintain --other-clients-closed` in the CLI, and a cleanup command with a confirmation dialog in Obsidian. Close all other clients of the vault first.

### Email delivery

- **Clearer failures.** Token, recipient, quota and sender problems now produce different messages in the CLI and plugin instead of one opaque reason. Obsidian shows one notice per day for a failed automatic email.
- **Retries that stay safe.** When a failure provably sent nothing, the day is released so automatic email can try again. A damaged delivery record now affects only its own date instead of blocking every later email.
- **Device tokens renew.** Hosted delivery verification tokens in regular use renew themselves and expire only after a year without use. If one is rejected, you are asked to send a new verification email.
- **Repair runs send mail.** If the report was written but a later step failed, rerunning the date now sends that day's email. Delivery records prevent duplicates. Note that rerunning an old date whose email was never attempted (for example, email was off then) can now send that day's email.
- **Better digest content.** Common math symbols stay readable, unknown LaTeX commands remain identifiable, and a day with no papers no longer links to a report that does not exist.
- The Email API key setting now says the key is stored only on this device and can be shown or hidden.

### Crashes, damaged files and recovery

- **Stuck days recover.** A date left "running" by a crashed process is recovered by the next run. Cancelling a workbench run now records the cancellation properly. A damaged `run-state.json` produces an error that names the file; **Clear run state** moves it aside and starts fresh, and `arxiv-daily status` reports the damage.
- **Obsidian `data.json`.** If it is unreadable or valid JSON but not a settings object, the plugin keeps a copy as `data.json.corrupt-<time>`, starts on defaults and tells you where the copy is. If it can't be copied, the plugin refuses to start rather than overwrite your settings. Write errors, such as a full disk, now reject the settings change with a failure notice instead of being hidden.
- **Dashboard.** An open Dashboard refreshes after a background daily run. Folder-case differences or a temporarily missing report folder no longer erase discovery history, and notes without a date no longer get a 1970 "seen" date (entries already holding one are not cleaned up). Clicking a completed date whose report was deleted regenerates it. The status bar no longer sticks on "Complete", "Failed" or a cancelled task. Enabling the scheduler no longer overwrites a finished run's outcome.

### CLI and workbench

- Settings changes keep the comments in `config.toml`, and the file is verified before it is saved.
- Installed cron entries now work: they use absolute paths, write a log, and keep a custom `XDG_CONFIG_HOME`.
- Unknown flags, bad dates and bad ids are rejected with exit code 2. `init` keeps an existing configuration by default and backs up before overwriting. `data export` writes atomically. `update` works on Windows and orders prereleases correctly.
- Diagnostic output masks short secrets without garbling research text.
- First daily report in the workbench: the button shows progress immediately and uses the latest announced day instead of stalling on an unannounced one. Failed days can be retried explicitly after you fix credentials.
- Smaller workbench fixes: search losing focus no longer replaces what you are reading; the "settings changed on disk" message says which actions are blocked (running and marking papers, not reading); Discard works while a field is focused; a damaged `workbench-ui.json` falls back to defaults.
- Settings now refuse topic values the daily run would reject, with a message naming the topic. `arxiv-daily run` exits 2 for such an existing config; other commands still open so you can fix it.

### Obsidian plugin: other changes

- Dashboard **More** menu has **Set paper mark…** (To read and other marks).
- **Add category** no longer saves a category on a stray click; it adds a draft row and saves once you pick one.
- Embedding dimension and secret fields save as a unit and restore on failure. The plugin README and Getting Started guides were rewritten to match the current product.
- A plugin that is disabled while loading no longer registers its commands, and an unloaded plugin refuses new work. The date picker's submit button now enables correctly. A superseded Dashboard library search is cancelled.

### DSH extension

- The workbench started by the DSH extension now stops when its DSH host is force-quit or crashes, instead of lingering with the schedule and API key still in memory. This ships in `dsh-arxiv-daily` 0.1.19, published alongside this release.

## Platform notes

- Unchanged from 0.6.2: the CLI's personal-library runtime is exercised on Linux (Node 20.19 and 22) only; the DSH extension is verified on Linux x64 only (now also against DSH 0.2.0-rc.2 and 0.2.1-alpha.2).
- The first scan of many PDFs without an arXiv id in their names takes about 3 seconds per title lookup, to respect arXiv's rate limits.

## Known issues

- Obsidian's hosted review still warns that rebuilding `main.js` from source doesn't match the released file (the CI-built native storage component for all six platforms). Unchanged from 0.6.2; the build provenance attestations still verify.
- Streaming idle timeouts apply to the CLI and workbench only. Obsidian's request API is buffered.
- Quiet-period index cleanup does not remove old model-specific paper files.
- Existing dashboard history entries that already hold a `1970-01-01` seen date are not cleaned up.
- Carried over from 0.6.0: the one-off native backup read on macOS arm64 (cause unknown, not reproduced since), the CLI personal library being Linux-only so far, and the DSH extension's narrow (Linux x64, Web profile) coverage.

## Install / upgrade

### CLI

```bash
npm install -g arxiv-daily@0.6.3
```

Or run `arxiv-daily update`. Existing configurations are not changed.

### Obsidian plugin

Update through Obsidian's Community plugins interface after the matching GitHub release is available. The release assets remain exactly `manifest.json`, `main.js`, and `styles.css`. No settings or data migration is required from 0.6.2.

### DSH extension (separate package)

Versions independently of arXiv Daily. Version 0.1.19 is published to npm alongside this release with the killed-host fix described above:

```bash
dsh plugin --profile web add dsh-arxiv-daily
```

In DSH Desktop, add `dsh-arxiv-daily` under Plugins → Add plugin.

## Compatibility

- **CLI package:** `arxiv-daily@0.6.3`.
- **Node.js:** 20.19.0 or newer for the CLI and plugin; Node.js 22 is also supported.
- **Obsidian minimum version:** unchanged at `1.5.7`.
- **CLI config:** unchanged; remains `schema_version = 1`. Comments in your existing `config.toml` are now preserved on edits.
- **Plugin data:** `data.json` and the paper index keep their schemas. Old novelty markers in existing reports are skipped and the leftover field is dropped from the index on save.
- **Email relay:** daily email needs the updated relay for token renewal; the project's hosted relay has been redeployed, so hosted-delivery users need no action. Self-hosters should redeploy with `npm run deploy` in `services/email-relay`; the new rate limiter requires a Durable Object migration.
- **Personal library:** processing remains opt-in on both hosts; existing reports and notes are not automatically rewritten.

## For maintainers

- Contributors now need Node.js 22.12 or newer to run the test suite (vitest 5). Shipped `engines` stay `>=20.19.0`, and the Node 20.19 compatibility job does not run vitest.
- Release tags must come from `main` or the release branch (`scripts/check-release-source.mjs`), and the DSH npm publish has the same gates as the CLI publish. DSH plugin now publishes to npm on `dsh-v` tags.
- Dependency and security updates: all six tracked lockfiles are now audited and are clean. Patched markdown-it, vite, vitest, KaTeX, happy-dom, fast-uri, msal-node and undici advisories; the `sharp` advisory from 0.6.2 is cleared by a wrangler upgrade. Dependabot now ignores major bumps that break supported runtimes (`@types/node` 26 in the relay, React 19 in DSH, `pdfjs-dist` 6).
- New real-UI acceptance suite (`npm run test:acceptance`) and a model-driven release exploration mode drive the workbench and a real Obsidian; the workbench journeys run on pull requests. The quality-eval scripts are documented in `scripts/quality-eval/README.md`.
- The relay now enforces verify limits atomically through a Durable Object, so it must be deployed with the documented command.

The release gate covers dependency audits, release tools, architecture boundaries, lint, workspace type checking and tests, production builds, the Obsidian submission requirements check, build smoke, and CLI package installation smoke.
