# arXiv Daily 0.4.1

## Overview

This release makes daily generation recoverable across interruptions in both the Obsidian plugin and CLI. Validated paper-filter decisions and completed per-paper summaries are checkpointed as private Vault data, so a cancelled or interrupted run can resume without repeating compatible LLM work.

Version 0.4.1 is the fix-forward publication of the 0.4.0 candidate. The immutable 0.4.0 tag failed its CI verification because the Core test worker exceeded the default heap before any GitHub Release, plugin assets, or npm package was published. 0.4.1 retains the same product changes and makes the release workflow use the already-proven memory-safe complete test invocation.

## Highlights

- **Recoverable paper filtering** — A validated daily filter batch is persisted before downstream work begins. An exact-compatible rerun reuses it instead of sending the same classification request again.
- **Recoverable per-paper summaries** — Each completed paper result is durably checkpointed before the next paper's LLM request starts. After interruption, compatible completed results are reused and only unfinished papers are generated.
- **Visible recovery lifecycle** — Normal logs show checkpoint `hit`, `miss`, and `persisted` events for both filtering and per-paper summaries.
- **Atomic daily reports remain authoritative** — Checkpoints are internal recovery state, never partial daily reports. A complete report is still committed all at once and takes precedence over checkpoint data.
- **Portable and safer Vault data** — CLI export/import carries checkpoint data and validates ZIP structure, paths, sizes, ratios, CRC32, links, staging, promotion, and rollback.
- **Stronger arXiv resilience** — Retry coordination, cache metadata, partial-discovery rejection, and existing-note protection reduce inconsistent output during upstream failures.
- **Clean cancellation logs** — Cancelling an LLM request no longer emits a misleading retry warning when no retry will be sent.
- **Refined plugin settings** — Shared declarative settings now drive provider, model, arXiv, topic, schedule, and email rows with improved rerender behavior.

## Recovery and data safety

Checkpoint files live under the configured index area:

```text
<indexDir>/filter-checkpoints/YYYY-MM-DD.json
<indexDir>/daily-summary-checkpoints/YYYY-MM-DD.json
```

Reuse is strict and misses when generation-relevant inputs change. Endpoint identity is stored only as a SHA-256 compatibility digest. Checkpoints may contain paper metadata, classifications, and generated summaries, so treat them and exported archives as sensitive Vault data. They do not contain API keys, plaintext endpoint URLs, or raw provider responses. Node-hosted checkpoint writes use mode `0600`.

A complete daily report remains authoritative and triggers best-effort cleanup. Compatibility fingerprints are not signatures or authenticity proofs; import only trusted archives into a quiescent Vault.

## Install / upgrade

### CLI

```bash
npm install -g arxiv-daily@0.4.1
# or:
arxiv-daily update
```

### Obsidian plugin

Update through Obsidian's Community plugins interface. The GitHub release contains exactly `manifest.json`, `main.js`, and `styles.css`.

## Compatibility

- **CLI package:** `arxiv-daily@0.4.1`.
- **Obsidian minimum version:** unchanged at `1.4.0`.
- **Config format:** remains `schema_version = 1`.
- **Vault migration:** none required.
- **Existing CLI configs, reports, and paper notes:** remain valid and preserved.
- **Upgrade source:** users on 0.3.5 should upgrade directly to 0.4.1; no 0.4.0 package or plugin release was published.

## For maintainers

The release workflow now regression-checks and runs the full workspace suite with an 8 GiB heap and one Vitest worker, matching the successful local release gate. The same immutable tag publishes plugin assets through GitHub Releases and the CLI through npm with provenance.
