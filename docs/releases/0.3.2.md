## Overview

arXiv Daily 0.3.2 rebuilds daily summarization around a sequential, per-paper pipeline with resilient fallback recovery, and makes scientific formulas more reliable in Obsidian. Daily reports stay consistent and rerunnable, MathJax-friendly Markdown is preserved end-to-end, and prompts plus a thin acceptance net guide models toward renderable `$...$` math. This release also adds low-friction in-plugin feedback links and keeps support for Obsidian 1.4.0.

## Highlights

- **Sequential per-paper daily summaries.** Each selected paper is summarized through a strict JSON contract at concurrency one, then assembled into the daily report deterministically. Completeness no longer depends on a multi-paper free-form Markdown reply that could omit papers.
- **Resilient per-paper fallback.** Validation failures and exhausted transport retries no longer collapse the whole day. Typed validation retries (up to three attempts), rescue assembly, and deterministic emergency assembly keep neighboring papers while recovering the failing entry.
- **Scientific math that renders in Obsidian.** Bilingual prompts use short rules and concrete good/bad examples so the model emits Obsidian inline `$...$` on the first pass. A thin script acceptance net keeps valid `$...$` byte-stable, converts only unambiguous `\(...\)` / simple `\[...\]` delimiters, and rejects unsafe math into the existing retry/fallback path instead of guessing repairs.
- **Consistent, rerunnable daily reports.** Rendered paper counts are derived from the report itself, missing eligible reports can be rerun, and Dashboard date controls remain reliable after deletes and completed runs.
- **Low-friction feedback.** Settings and Dashboard link to GitHub Issues. Bug reports open a blank issue with only the plugin version prefilled; feature requests open a blank issue. No heavy form is forced.
- **Community Plugin metadata.** Manifests include `authorUrl` pointing at the public repository for the Community directory and About surfaces.

## Daily summarization

- Replaces the multi-paper free-form daily summary prompt with per-paper structured fields: `coreProblem`, `keyMethod`, `mainResult`, `whyRelevant`, and `limitations`, plus a stable paper `id`.
- Assembles topic sections and paper blocks in deterministic order from accepted structured results (and trusted fallbacks), so report shape does not depend on model-authored Markdown scaffolding.
- Uses bilingual system prompts and language-matched injection guards for English and Chinese summary paths.
- Surfaces progress for summarize-daily stages from `1/N` through `N/N` during sequential generation.
- Distinguishes validation failures from transport exhaustion and permanent provider/configuration errors so recovery stays typed and per-paper.

## Fallback and recovery

- On invalid JSON, schema, empty fields, or invalid scientific math, retries the same paper with short trusted correction guidance (no untrusted model-text replay).
- After validation is exhausted, falls back for that paper only (for example to a trusted original abstract path) while keeping successful neighbors.
- On exhausted transient LLM transport, returns a transport-exhausted fallback for that paper instead of failing the whole run.
- Rescue and emergency assembly paths produce a usable daily report when structured generation cannot fully complete.
- Trusted report rendering and parser safeguards are centralized so fallback and rescue content stay safe for Markdown persistence and later re-parse.

## Scientific Markdown and math

- Hardens daily-report Markdown emission so scientific and user-authored inline math remain readable MathJax input rather than being corrupted by over-escaping.
- Validates structured semantic fields with a conservative single-line math contract:
  - Accept valid `$...$` unchanged.
  - Rewrite only explicitly delimited `\(...\)` and simple one-line `\[...\]` to `$...$`.
  - Reject bare TeX, display math, multiline fields, unbalanced grouping, and raw-HTML-shaped angle brackets inside math (for example `$<z>$`) that would be treated as HTML tags.
- Prompts require `\langle ... \rangle` (or `\left< ... \right>`) for ensemble averages / expectations, while ordinary comparisons such as `$z<0.5$` remain fine.
- Detail-note prompts align on supported delimiters (`$...$` / `$$...$$`) and the same angle-bracket guidance; daily semantic fields remain inline-only.
- Over-rejection of ambiguous prose is preferred to silent mis-rewrite; rejected papers use the existing per-paper retry/fallback boundary.

## Dashboard and reliability

- Daily report paper counts used for consistency checks come from rendered paper blocks, not optimistic model claims.
- Eligible missing daily reports can be regenerated; completed-but-deleted calendar dates remain interactive when appropriate.
- Date-picker and Dashboard run-for-date flows are more reliable, including post-run refresh behavior.
- History sync and selection markers stay consistent with scientific Markdown and structured summary recovery from daily files.
- Detached Dashboard and Settings feedback actions open external URLs through the existing resource opener (pop-out-window safe).

## Feedback and Obsidian compatibility

- Settings → **Help & feedback** and Dashboard → **More** provide:
  - Report a bug
  - Request a feature
  - Documentation
  - Repository
- Bug links prefill only `- arXiv Daily: <version>`; feature links open a blank issue for maximum freedom.
- GitHub blank issues remain enabled; structured issue questionnaires are not forced from the plugin.
- Root and plugin `manifest.json` stay identical and include `authorUrl`: `https://github.com/tdccccc/arxiv-daily`.
- Minimum supported Obsidian version remains **1.4.0**.
- Official `eslint-plugin-obsidianmd` warnings were reduced (prefer-create-el auto-fixes and a tighter local warning budget). Settings still use the classic `PluginSettingTab.display` API for 1.4.0 compatibility; migration to `getSettingDefinitions` is intentionally deferred.

## Data compatibility

- Existing daily reports, detail notes, command IDs, output paths, and Paper Index files remain readable.
- No manual data migration is required.
- Structured daily fields continue to project into the Paper Index when present; older entries without them remain valid.
- Settings and run-state formats are unchanged for upgrade purposes.

## Security and privacy

- Feedback links open GitHub in the browser; the plugin does not transmit vault contents, API keys, or paper text to GitHub automatically.
- LLM calls for daily/detail summarization and existing selector flows still send configured paper content to the user-chosen provider under the same assumptions as previous releases.
- Saved API keys remain plaintext in Obsidian plugin `data.json` for compatibility; this release does not add keyring or encrypted secret storage.
- Math and Markdown acceptance reject raw-HTML-shaped constructs that would break rendering; they do not introduce a new network surface.
- The plugin does not send client-side telemetry.

## Install

Download these three assets and copy them directly to:

```text
<your-vault>/.obsidian/plugins/arxiv-daily/
```

- `manifest.json`
- `main.js`
- `styles.css`

Restart Obsidian, then enable **arXiv Daily** under **Settings → Community plugins**.

If you already use Community Plugins or BRAT, update to **0.3.2** and reload the plugin.

## Breaking changes

There are no data-format or command-ID breaking changes. Existing users can upgrade in place.

Behavioral notes (not schema breaks):

- Daily summarization is sequential per paper rather than one multi-paper free-form completion; runtime characteristics and partial-failure behavior therefore differ from 0.3.1.
- Daily semantic fields expect Obsidian inline `$...$` math; unsupported delimiters and bare TeX are corrected via retry or per-paper fallback instead of being left unrenderable.
- As always, keep a Vault backup before upgrading community plugins.
