# arXiv Daily 0.6.8

## Overview

This is a small follow-up release for the Obsidian plugin. It resolves the two needs-review items left by the post-0.6.7 model exploration, both around the Dashboard's manual run controls: a skipped "Run today" used to leave a misleading "running…" notice next to its result, and a second manual request for a date that was already running could queue behind the first run and then report a stale "already done". The CLI and workbench are unchanged; the DSH extension gets a matching build because it bundles the CLI.

## Fixes

- **A skipped manual run reports only the skip.** When the scheduler skips a manual run (already done, lock held, or not eligible), the interim "running for DATE…" notice is hidden and the final result is the only message left. This covers the Dashboard's Run today and calendar entries, "Run for date…"/"Force run for date…", the command palette, and the settings guide's "Generate first report".
- **One manual run per date at a time.** A second manual request for the same date is now rejected immediately with "arXiv Daily: DATE is already running" instead of waiting behind the first run and then reporting "already done". The guard is shared by the Dashboard toolbar, the empty state, the calendar, the "More" menu, the command palette, and the settings guide. Different dates remain independent, and the scheduler's cross-process lock still coordinates separate windows.

## Exploration notes

- **The keyboard-only "More arXiv Daily actions" menu item is not a product defect.** The menu is an Obsidian-native `Menu`: its items are plain non-focusable elements, and Obsidian registers Arrow/Enter/Escape handlers on the menu's own keyboard scope (`resources/obsidian.asar` → `app.js`, read-only inspection on 2026-11-24), so Escape closes it in a real session regardless of DOM focus. The exploration harness only sends key presses while DOM focus is inside the plugin surface, so the keyboard-only persona cannot drive the native menu. This is a harness limitation; the plugin does not manage focus for Obsidian's own menus.

## Upgrade notes

- **No configuration or data migration is required.** Reports, notes, indexes, and settings are read as before.

## Known issues

- Carried over from 0.6.7: a regenerated report is filtered from scratch, so when several papers tie at the daily limit the new report may pick a different one; and the scheduling and Dashboard items carried since 0.6.4/0.6.5.

## Install / upgrade

### CLI

```bash
npm install -g arxiv-daily@0.6.8
```

Or run `arxiv-daily update`.

### Obsidian plugin

Update through Obsidian's Community plugins interface after the matching GitHub release is available. The release assets remain exactly `manifest.json`, `main.js`, and `styles.css`.

## Compatibility

- **CLI package:** `arxiv-daily@0.6.8`.
- **Node.js:** 20.19.0 or newer for the CLI and plugin; Node.js 22 is also supported.
- **Obsidian minimum version:** unchanged at `1.5.7`.
- **CLI config:** unchanged, `schema_version = 1`.
- **Plugin data:** unchanged.

## For maintainers

- The manual-run guard is `plugin/src/services/manual-run-gate.ts` (per plugin instance, keyed by date); every manual run surface acquires it before showing the running notice and releases it in a `finally`.
- The exploration harness exempts only the product's expected console error for a date older than the oldest `/recent` bucket (`scripts/acceptance/exploration-obsidian.mjs`, `isExpectedOutOfRangeDateLog`): console errors only, exact prefix; page exceptions and every other console error still fail the scenario. Covered by `scripts/tests/acceptance-exploration-host.test.mjs`.
- The exploration findings and their evidence are recorded in `docs/issue/2026-11-24-exploration-followups.md`.
