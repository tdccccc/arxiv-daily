# arXiv Daily 0.6.8

## Overview

This is a small follow-up release for the Obsidian plugin. It resolves the two needs-review items left by the post-0.6.7 model exploration, both around the Dashboard's manual run controls: a skipped "Run today" used to leave a misleading "running…" notice next to its result, and a second manual request for a date that was already running showed another "running…" notice before the scheduler's generic "lock held" skip. The CLI and workbench are unchanged; the DSH extension gets a matching build because it bundles the CLI.

## Fixes

- **A manual run reports only its final outcome.** The interim "running for DATE…" notice is hidden as soon as the run settles, so the final result — or the error notice when the run throws — is the only feedback left. This covers normal completion, a skip (already done, lock held, or not eligible), a transient/permanent failure, a pending result, and a thrown error. The same pattern is used by the Dashboard's Run today and calendar entries, "Run for date…"/"Force run for date…", the command palette, and the settings guide's "Generate first report".
- **One manual run per date at a time.** A second manual request for the same date is now rejected immediately with "arXiv Daily: DATE is already running" instead of showing its own "running…" notice and then the scheduler's generic skip ("lock held", or "already done" if the first run finished in between). The guard is shared by the Dashboard toolbar, the empty state, the calendar, the "More" menu, the command palette, and the settings guide. Different dates remain independent, and the scheduler's cross-process lock still coordinates separate windows.

## Exploration notes

- **The keyboard-only "More arXiv Daily actions" menu item is not a product defect.** The menu is an Obsidian-native `Menu`: its items are plain non-focusable elements, and Obsidian registers Arrow/Enter/Escape handlers on the menu's own keyboard scope (`resources/obsidian.asar` → `app.js`, read-only inspection on 2026-11-24), so Escape closes it in a real session regardless of DOM focus. The exploration harness only sends key presses while DOM focus is inside the plugin surface, so the keyboard-only persona cannot drive the native menu. This is a harness limitation; the plugin does not manage focus for Obsidian's own menus.

## Upgrade notes

- **No configuration or data migration is required.** Reports, notes, indexes, and settings are read as before.

## Known issues

- Carried over from 0.6.7: a regenerated report is filtered from scratch, so when several papers tie at the daily limit the new report may pick a different one; and the scheduling and Dashboard items carried since 0.6.4/0.6.5.

## Install / upgrade

### CLI

```bash
npm install -g arxiv-daily@0.6.8
```

Or run `arxiv-daily update`.

### Obsidian plugin

Update through Obsidian's Community plugins interface after the matching GitHub release is available. The release assets remain exactly `manifest.json`, `main.js`, and `styles.css`.

## Compatibility

- **CLI package:** `arxiv-daily@0.6.8`.
- **Node.js:** 20.19.0 or newer for the CLI and plugin; Node.js 22 is also supported.
- **Obsidian minimum version:** unchanged at `1.5.7`.
- **CLI config:** unchanged, `schema_version = 1`.
- **Plugin data:** unchanged.

## For maintainers

- The manual-run protocol lives in `plugin/src/services/manual-run-gate.ts`: `runManualDate` acquires a per-plugin, per-date gate, shows the interim notice, and always hides that notice and releases the gate when the run settles; every manual surface uses it.
- The exploration harness exempts only the product's expected console error for a date older than the oldest `/recent` bucket (`scripts/acceptance/exploration-obsidian.mjs`, `isExpectedOutOfRangeDateLog`): console errors only, exact prefix, and the run date must match the offending date it reports; page exceptions, other console errors, and mismatched-date messages still fail the scenario. Covered by `scripts/tests/acceptance-exploration-host.test.mjs`.
- The exploration findings and their evidence are recorded in `docs/issue/2026-11-24-exploration-followups.md`.
