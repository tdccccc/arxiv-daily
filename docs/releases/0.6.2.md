# arXiv Daily 0.6.2

## Overview

This release clears the errors Obsidian's hosted community review raised against 0.6.1, and fixes the CLI's standalone reading workbench (`arxiv-daily ui`) on first run. The review failures came from CLI and shared runtime code, not from the Obsidian plugin itself, so the Obsidian plugin has no behavior changes. The Claude Code CLI integration has been removed from the repository. The independently versioned DSH extension is not part of this release.

## Highlights

### Obsidian hosted review: 0.6.1 errors cleared

- Obsidian's hosted review scans every production source tree in the repository, not just the plugin. It marked 0.6.1 as **Failed** over two kinds of findings, both in code the Obsidian plugin never runs:
  - The CLI's browser workbench assigned HTML strings to `innerHTML`/`outerHTML`/`insertAdjacentHTML`.
  - The CLI's personal-library runtime loaded its optional PDF-parsing and embedding components through dynamic `import()` calls.
- The workbench now builds its pages from DOM elements directly. Paper titles, abstracts, saved documents and math formulas render the same as before.
- The library runtime now loads both components through Node's `require`. This works on every supported Node version (20.19.0 and newer).
- A preview scan of these changes on Obsidian's review page completed without the errors.

### Standalone workbench: first run no longer traps you in Settings

These fixes apply when `arxiv-daily ui` starts without a CLI configuration file:

- **The save root defaults to `~/arxiv-daily`**, the same default `arxiv-daily init` uses. Edits now autosave from the first change. Previously the field started empty, nothing could be saved until it was filled, and closing Settings discarded what you had typed. You can still change the folder. Opening and closing Settings without edits writes nothing.
- **Settings can always be closed** with the dialog's × or Escape. Before, clicking **完成/Done** did nothing visible until a save root was filled in. If you clear the save root after typing other settings, closing first asks whether to go back and fill it in or discard those entries.
- **After closing, the workbench shows a "setup not finished" panel** with a button back into Settings. It no longer reopens Settings on every action.
- **Interface language changes apply to the whole workbench immediately**, not only after Settings closes.
- **The redundant 完成/Done button is gone.** Settings save automatically, and the footer shows the save status (with a warning when the save root is missing).

### Claude Code CLI integration removed

- The `extensions/claude-code-arxiv-daily` integration is no longer maintained in this repository; its references are gone from the README and guides. Installing this release doesn't remove a copy you already installed in Claude Code, but that copy will receive no further updates. Uninstall it from Claude Code if you no longer use it.
- The README is now a short feature overview. Details moved to the Getting Started guides and the CLI README, including the personal library's read-only access and authorization notes and the advice to `chmod 600` the CLI config file.

## Platform notes

- Unchanged from 0.6.1: the CLI's personal-library runtime is exercised on Linux (Node 20.19 and 22) only; the DSH extension is verified on Linux x64 only.

## Known issues

- Obsidian's hosted review still warns that rebuilding `main.js` from source doesn't match the released file. Release builds embed the CI-built native storage component for all six platforms, which a plain source checkout without a C++ toolchain can't reproduce. This has been the case since 0.6.0. The release assets' build provenance attestations still verify that they were built by this repository's release workflow.
- Carried over from 0.6.0: the one-off native backup read on macOS arm64 (cause unknown, not reproduced since), the CLI personal library being Linux-only so far, and the DSH extension's narrow (Linux x64, Web profile) coverage.

## Install / upgrade

### CLI

```bash
npm install -g arxiv-daily@0.6.2
```

Or run `arxiv-daily update`. Upgrading is recommended if you use `arxiv-daily ui`. Existing configurations are not changed.

### Obsidian plugin

Update through Obsidian's Community plugins interface after the matching GitHub release is available. The release assets remain exactly `manifest.json`, `main.js`, and `styles.css`. No settings or data migration is required from 0.6.1, and the plugin's behavior is unchanged.

### DSH extension (separate, not published here)

Versions independently of arXiv Daily and is not affected by this release.

## Compatibility

- **CLI package:** `arxiv-daily@0.6.2`.
- **Node.js:** 20.19.0 or newer for the CLI and plugin; Node.js 22 is also supported.
- **Obsidian minimum version:** unchanged at `1.5.7`.
- **CLI config:** unchanged; remains `schema_version = 1`. The workbench only writes the default save root once you edit a setting on first run.
- **Personal library:** processing remains opt-in on both hosts; existing reports and notes are not automatically rewritten.

## For maintainers

- `npm run lint:review` now includes `eslint-plugin-no-unsanitized` (`property` and `method` rules), so the hosted review's unsafe-HTML and dynamic-import findings can be reproduced locally before tagging. It reports zero such findings for this release.
- The CLI test setup patches happy-dom's missing `document.compatMode`; without it, KaTeX's DOM renderer disables itself in tests.
- The email relay's separate dependency audit currently fails on a new `sharp` advisory, reached through `wrangler`'s dev tooling. It isn't part of any shipped bundle or of this release gate, and will be handled separately.

The release gate covers dependency audits, release tools, architecture boundaries, lint, workspace type checking and tests, production builds, the Obsidian submission requirements check, build smoke, and CLI package installation smoke.
