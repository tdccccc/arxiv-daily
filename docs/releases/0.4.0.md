# arXiv Daily 0.4.0

## Overview

This release makes daily generation recoverable across interruptions in both the Obsidian plugin and CLI. Validated paper-filter decisions and completed per-paper summaries are checkpointed as private Vault data, so a cancelled or interrupted run can resume without repeating compatible LLM work.

It also strengthens arXiv request recovery, CLI data portability, plugin settings maintainability, and release integrity. Cancellation now stops cleanly without logging a retry that will never be sent.

## Highlights

- **Recoverable paper filtering** — A validated daily filter batch is persisted before downstream work begins. An exact-compatible rerun reuses it instead of sending the same classification request again.
- **Recoverable per-paper summaries** — Each completed paper result is durably checkpointed before the next paper's LLM request starts. After interruption, compatible completed results are reused and only unfinished papers are generated.
- **Visible recovery lifecycle** — Normal logs now show checkpoint `hit`, `miss`, and `persisted` events for both filtering and per-paper summaries.
- **Atomic daily reports remain authoritative** — Checkpoints are internal recovery state, never partial daily reports. A complete report is still committed all at once and takes precedence over checkpoint data.
- **Portable checkpoint data** — CLI data export/import includes active `.index` checkpoint data, allowing recovery state to move with a trusted Vault archive.
- **Safer archive import** — ZIP imports now validate paths, structure, counts, sizes, compression ratios, CRC32, link/target safety, staging, promotion, and rollback before applying imported Vault data.
- **Stronger arXiv resilience** — Request retry coordination, cache metadata, partial-discovery rejection, and existing-note protection reduce inconsistent output during upstream failures.
- **Clean cancellation logs** — Cancelling an LLM request no longer emits a misleading retry warning when no retry will be sent.
- **Refined plugin settings** — The settings tab now uses the shared declarative settings API for provider, model, arXiv, topic, schedule, and email rows, with improved rerender behavior and Obsidian 1.13+ topic layout.

## Recovery behavior

Checkpoint files live under the configured index area:

```text
<indexDir>/filter-checkpoints/YYYY-MM-DD.json
<indexDir>/daily-summary-checkpoints/YYYY-MM-DD.json
```

Reuse is intentionally strict. A checkpoint misses when generation-relevant inputs change, including the rendered request, paper content/order, topics, provider, model, effective endpoint, or reasoning settings. The endpoint is stored only as a SHA-256 compatibility digest—not as a plaintext URL.

Checkpoint files and their backups are sensitive Vault data because they may contain paper titles, abstracts, classifications, and generated summaries. Node-hosted writes use mode `0600`. They do not contain API keys, plaintext endpoint URLs, or raw provider responses.

A validated empty filter result can remain until compatible input changes or it is safely removed while no arXiv Daily process is active. Successful report commit and existing-report recovery both attempt best-effort checkpoint cleanup.

## Install / upgrade

### CLI

```bash
npm install -g arxiv-daily@0.4.0
# or, from a version that provides the update command:
arxiv-daily update
```

Fresh CLI setup:

```bash
npm install -g arxiv-daily
arxiv-daily init
arxiv-daily run --today
```

### Obsidian plugin

Update arXiv Daily through Obsidian's Community plugins interface. The GitHub release contains exactly:

- `manifest.json`
- `main.js`
- `styles.css`

## CLI data portability

Export and import continue to use:

```bash
arxiv-daily data export --out arxiv-daily-data.zip
arxiv-daily data import arxiv-daily-data.zip
```

Only import archives from a trusted source into a quiescent Vault. Compatibility fingerprints detect generation-input changes; they are not signatures or authenticity proofs. Archive rollback protects ordinary runtime failures, but a crash or power loss cannot provide a true cross-file filesystem transaction.

## Compatibility

- **CLI package:** `arxiv-daily@0.4.0` (bin `arxiv-daily`).
- **Obsidian minimum version:** unchanged at `1.4.0`.
- **Config format:** remains `schema_version = 1`.
- **Vault migration:** none required.
- **Existing reports and paper notes:** preserved; an existing complete daily report remains authoritative.
- **Existing CLI configs:** remain valid.
- **Checkpoint schemas:** internal, versioned recovery data; incompatible entries safely miss rather than being reused.

## Upgrade notes from 0.3.5

1. Upgrade the CLI and/or plugin normally; no config or Vault migration is required.
2. Interrupted runs started after upgrading can reuse only checkpoints generated with exact-compatible settings and inputs.
3. Keep the Vault and exported archives trusted and avoid concurrent imports or manual checkpoint edits while arXiv Daily is running.
4. If you intentionally want to discard recovery state, remove the date-specific checkpoint files only while no arXiv Daily process is active. Do not remove an existing completed daily report to force checkpoint recovery.

The release workflow publishes the Obsidian assets through GitHub Releases and the CLI through npm from the same immutable `0.4.0` tag. Both JavaScript bundles include the locked pako notice, and release assets/npm publication carry build provenance when the configured credentials are available.
