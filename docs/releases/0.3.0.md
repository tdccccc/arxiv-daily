## Overview

arXiv Daily 0.3.0 moves the Obsidian plugin and Node CLI onto one shared TypeScript Core. Host-specific adapters provide storage, HTTP, markup, secrets, progress, and resource-opening behavior; no daemon, protocol layer, or second business implementation was introduced.

## Highlights

- Adds cooperative cancellation across scheduled and manual daily runs, detail summaries, and PDF downloads.
- Adds folded generation metrics to daily reports and detail notes, covering elapsed time, logical LLM calls, HTTP attempts, and provider-reported token usage without estimating cost.
- Hardens API-key presentation and log, diagnostic, notice, and presented-error redaction.
- Adds relevance-ranked local Dashboard search and Similar Papers discovery using deterministic lexical retrieval, with no embedding service, database, LLM call, or extra network request.
- Confines generated output and detail-summary trash operations to validated Vault-relative paths.
- Rebuilds arXiv and PDF links from validated canonical arXiv IDs rather than trusting persisted URLs.

## Architecture and CLI

- `@arxiv-daily/core` is the single host-neutral business implementation.
- The Obsidian plugin uses Obsidian adapters; the CLI uses `@arxiv-daily/node-runtime`.
- The canonical CLI bundle is `apps/cli/dist/arxiv-daily-cli.cjs`.
- `plugin/arxiv-daily-cli.cjs` remains a compatibility copy.
- `arxiv_daily.py` remains a deprecated delegating shim.

## Compatibility

- Existing plugin settings, Paper Index schema 1/2 files, generated daily reports, detail notes, and cache keys remain readable.
- No Paper Index schema or Markdown migration is required.
- Existing command IDs are retained, including `arxiv-daily:cancel-current-run`.
- Output-path changes select a new destination; they do not move existing notes, PDFs, or index files.
- Minimum supported Obsidian version remains 1.4.0. The 0.3.0 candidate was also upgrade-tested in the isolated test Vault on Obsidian 1.12.7.

## Security and privacy

- Saved plugin API keys remain plaintext in Obsidian's local plugin `data.json`; this release does not claim encrypted or keyring-backed storage.
- A configured key is represented by a fixed sentinel and is not rendered back into Settings inputs or copied into diagnostics.
- Known secrets and common credential forms are redacted before logs, notices, diagnostics, and presented errors are emitted.
- Plugin caches may contain arXiv HTML, abstracts, and source archives. They expire after the configured retention period through opportunistic cleanup and can be removed while the plugin is stopped. See the README for exact locations.
- The plugin does not send client-side telemetry.

## Operational semantics

- Cancellation is cooperative. Work checks its cancellation signal at safe boundaries.
- An Obsidian `requestUrl` call that has already been issued cannot be physically aborted and may finish before cancellation unwinds; the UI reports cancellation as requested rather than claiming remote work stopped immediately.
- Token metrics use provider-reported values only. Missing provider usage is reported as unavailable or incomplete, and no monetary cost is estimated.

## Install

Download these three assets and copy them directly to:

```text
<your-vault>/.obsidian/plugins/arxiv-daily/
```

- `manifest.json`
- `main.js`
- `styles.css`

Restart Obsidian, then enable **arXiv Daily** under **Settings → Community plugins**.

## Breaking changes

There are no data-format or command-ID breaking changes. Existing users can upgrade in place. As always, keep a Vault backup before upgrading community plugins.
