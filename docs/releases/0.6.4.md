# arXiv Daily 0.6.4

## Overview

This is a small release that changes how daily reports read. Every summary field is visible again, and the per-paper block of matched directions and source sections is gone.

The Obsidian plugin and the CLI (including the standalone workbench, `arxiv-daily ui`) both change, because they share the same report generator. Email delivery is unchanged.

## Highlights

### Daily reports: the whole summary at a glance

- **All five summary fields are shown flat.** Since 0.5.0 each paper showed only "Core results", with research problem, method design, research value and scope folded into a "Background, methods and limits" callout. New reports list all five fields as plain bullets again, in the order research problem, method design, core results, research value, scope and limits.
- **No more "Matched directions and sources" block.** New reports no longer say which topic direction selected a paper or which sections of the paper the summary drew on. Papers in a topic section are there because the filter judged them relevant to that topic.
- **Summary sources are still kept, outside the report.** The sections a summary was based on are written to the paper index, so the workbench paper page still shows them under "Summary sources". Papers that fall back to their original abstract record none.
- **Existing reports are not rewritten.** Reports from 0.5.0–0.6.3 keep their folded layout and still read back correctly, as do pre-0.5 reports.

## Known issues

- Papers whose summary failed and that fell back to the original abstract carry a hidden marker that Obsidian's Live Preview shows as a grey comment line. This predates this release.
- Opening a daily report doesn't give you a direct way to open a paper's own reading page unless it has a separate paper note. This predates this release.
- Carried over from 0.6.3: Obsidian's hosted review warning about rebuilding `main.js`, buffered streaming in Obsidian, quiet-period cleanup not removing old model-specific paper files, existing `1970-01-01` dashboard seen dates, and the 0.6.0 platform caveats.

## Install / upgrade

### CLI

```bash
npm install -g arxiv-daily@0.6.4
```

Or run `arxiv-daily update`. Existing configurations are not changed.

### Obsidian plugin

Update through Obsidian's Community plugins interface after the matching GitHub release is available. The release assets remain exactly `manifest.json`, `main.js`, and `styles.css`. No settings or data migration is required from 0.6.3.

## Compatibility

- **CLI package:** `arxiv-daily@0.6.4`.
- **Node.js:** 20.19.0 or newer for the CLI and plugin; Node.js 22 is also supported.
- **Obsidian minimum version:** unchanged at `1.5.7`.
- **CLI config:** unchanged; remains `schema_version = 1`.
- **Plugin data:** `data.json` and the paper index keep their schemas. Summaries already cached for an unfinished day are reused and come out in the new layout.

## For maintainers

- The topic-direction marker is no longer written. Its parser stays for reading old reports.
- The rescue contract and its prompts no longer carry source sections. The pipeline merges source sections from the structured summary slots into the paper index after the report is written.

The release gate covers dependency audits, release tools, architecture boundaries, lint, workspace type checking and tests, production builds, the Obsidian submission requirements check, build smoke, and CLI package installation smoke.
