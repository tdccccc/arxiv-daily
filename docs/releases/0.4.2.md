# arXiv Daily 0.4.2

## Overview

This release strengthens failure handling and durable state across filtering, Paper Index updates, scheduled completion, settings changes, and email delivery. It also brings the VS Code companion back in line with the current CLI and expands independent CI coverage for the repository's separately shipped products.

## Highlights

- **Fail-closed paper filtering** — Invalid model JSON or an invalid filter contract stops the run as a transient failure. Untrusted raw model output is not written into checkpoints, Paper Index data, or logs.
- **Recoverable Paper Index** — Classified primary, backup, and legacy reads preserve valid data through interrupted writes and corrupted primary files. Queued mutations prevent in-process stale read/write races.
- **Durable scheduler completion** — A day is reported as completed only after the authoritative run state is confirmed on disk. Completion callbacks and user-visible success happen after that commit.
- **Transactional plugin settings** — Settings changes are serialized and validated on a candidate configuration. Persistence succeeds before live settings, stores, timers, and runtime effects are replaced.
- **Safer automatic email delivery** — Automatic delivery uses stable recipient-hashed idempotency identities, private immutable claim generations, host namespace guards, and fail-closed outcomes for ambiguous provider or persistence results. Test sends use independent random identities.
- **Hosted relay transition compatibility** — The hosted client accepts the relay's canonical success response and two strictly bounded legacy success shapes. Legacy provider IDs are validated and discarded; malformed, oversized, duplicate-member, or extended responses remain ambiguous and block automatic resend.
- **Current VS Code command bridge** — The companion invokes only `arxiv-daily run --today` and `arxiv-daily run --id <id>`, matching the current CLI parser.
- **Independent product verification** — Root workspaces, the email relay, and the VS Code companion have explicit product inventory and separate release-equivalent or product-specific CI gates.

## Email delivery safety

Automatic email delivery prioritizes avoiding duplicate sends when the provider outcome cannot be proved. A provider attempt with an ambiguous response, a locally unrecorded acceptance, or unreadable delivery state remains blocked for automatic retry and requires manual inspection. The system does not run an email outbox or background retry daemon and does not claim distributed exactly-once delivery.

Hosted success bodies are limited to 4096 characters and exactly one of these JSON shapes:

```json
{"ok":true}
```

```json
{"ok":true,"id":"bounded-provider-id"}
```

```json
{"ok":true,"id":"bounded-provider-id","deduped":true}
```

The `id` is limited to 128 characters and is not exposed in results, logs, or delivery state. Other fields, duplicate JSON members, invalid types, empty IDs, and oversized responses are treated as ambiguous.

## Install / upgrade

### CLI

```bash
npm install -g arxiv-daily@0.4.2
# or:
arxiv-daily update
```

### Obsidian plugin

Update through Obsidian's Community plugins interface after the matching GitHub release is available. The release assets remain exactly `manifest.json`, `main.js`, and `styles.css`.

Users of Official delivery should upgrade the plugin or CLI before the hosted relay protocol cutover. A later operational cutover may require requesting a new verification link and replacing the hosted token; follow the instructions published with that maintenance event.

## Compatibility

- **CLI package:** `arxiv-daily@0.4.2` after publication.
- **Obsidian minimum version:** unchanged at `1.4.0`.
- **Config format:** remains `schema_version = 1`.
- **Paper Index:** reads existing schemas 1–4 and writes schema 4; no manual migration is required.
- **Delivery state:** remains schema 1 for older-reader compatibility; private sidecars carry the stronger claim generation.
- **Existing configs, reports, paper notes, and valid indexes:** remain supported.

## For maintainers

The release gate covers release tools, architecture boundaries, lint, workspace type checking, all workspace tests, production builds, and smoke checks. The email relay and VS Code companion retain independent lockfiles and workflows; relay verification performs a Wrangler dry-run only and does not deploy or read production credentials.
