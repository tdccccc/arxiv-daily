# arXiv Daily 0.6.7

## Overview

This is a bug-fix release for the Obsidian plugin and the CLI (including the standalone workbench, `arxiv-daily ui`). It resolves the 2026-11-22 code review findings and the regressions found by an independent review of that fix set. The main themes are: a daily report and its paper index now commit as one unit; a personal-library index survives cancellation and settings changes; first-run settings act on what you just typed; and the Dashboard and storage behave correctly under Obsidian.

The DSH extension (`dsh-arxiv-daily@0.1.23`) gets a matching build because it bundles the CLI.

## Fixes

- **An interrupted daily run no longer loses the day's papers.** The report is written first and the paper index is committed only after it; if the run is cancelled or the index write fails, the next run rebuilds the missing index entries from the committed report instead of silently skipping them. Zero-match days clean their checkpoints, and a corrupt summary checkpoint rebuilds instead of making the date fail repeatedly and spending an LLM call on every retry.
- **Detail notes link back to their daily report.** Notes written before the report existed receive the `published` daily wikilink after the report commits, including on a retry that does not rewrite the note and when no paper index is configured.
- **Personal-library indexing is safer.** Paper documents are deleted only after the manifest commits, so switching models or cancelling a rebuild keeps the previous index readable. Revoking processing authorization, or changing the embedding mode/endpoint/model/key, cancels a running remote index so no further titles or abstracts are sent to the old endpoint. An incomplete remote embedding configuration is reported as configuration state rather than as an unreadable index, and stale preparation errors clear once the index verifies.
- **The local embedding model is reused.** Searches, index runs and diagnostics share one ONNX session instead of rebuilding a ~130 MB model for every query; a failed first download can be retried, and the session is released only when it is no longer in use.
- **First-run settings work in the order people use them.** "Get models" after pasting an API key or changing a base URL now uses the new values, and the legacy "Send test"/"Send verification" buttons flush the draft key or recipient first. A saved custom IANA timezone stays visible, and custom arXiv categories can be added on both settings UIs.
- **Dashboard fixes.** A foreground arXiv recent-dates refresh no longer repaints an empty index over Loading; the calendar updates when the refresh completes and the timeout notice clears when the background refresh finishes. Similar-papers defaults to Daily when no library is connected, "Show All" keeps the tab state and paging in sync, and a failed library search can be retried from Refresh. History rebuilds read the current `published` frontmatter.
- **Obsidian storage fixes.** Removing a path is recursive and idempotent, so old personal-library search-index generations are actually deleted and `run-history.jsonl` keeps rotating past 512 KB. A stat permission/I/O failure is no longer treated as "already gone".
- **PDF and parser fixes.** arXiv HTML captcha/error pages returned with HTTP 200 are rejected instead of saved as `.pdf` and recorded in `papers.json`. Uppercase UTF-16LE PDF titles decode correctly, oversized hex titles no longer overflow the call stack, and out-of-range HTML entities no longer fail title extraction.
- **Model-client fixes.** An Anthropic preset pointed at a proxy uses OpenAI-compatible parameters and can drop a rejected optional field; native Anthropic thinking budgets, including adaptive thinking, leave room for the visible answer instead of consuming the whole `max_tokens`.
- **Email fixes.** Hosted delivery and verification pass cancellation through instead of reporting an unreachable relay, and Resend display names containing RFC 5322 special characters are quoted and escaped.

## Upgrade notes

- **A `.pdf` that was previously saved from an HTML error page is not repaired automatically.** Download the PDF again to replace it; new downloads are checked for the `%PDF-` header before they are recorded.
- **A corrupt summary checkpoint now rebuilds on the next run.** No manual deletion is needed. Dates already marked permanently failed still need a normal rerun.
- **The local embedding model stays in memory while the plugin is loaded.** Expect roughly 130 MB after the first local search or index run; it is released on plugin unload or when switching to remote embedding.
- **Anthropic proxies now receive `reasoning_effort` rather than native `thinking`/`output_config`.** If the proxy rejects that field, arXiv Daily retries without it instead of failing the date.
- **No configuration or data migration is required.** CLI config stays at `schema_version = 1`, plugin data is unchanged, and existing reports, notes and indexes are read as before.

## Known issues

- A regenerated report is filtered from scratch. When several papers tie at the daily limit, the new report may pick a different one; a paper that dropped out keeps its entry and note from the first run.
- Carried over from 0.6.5: a date on which arXiv announced nothing may still be retried before it is recognised as empty in every scheduling path; and the items listed under 0.6.4 for the quiet-period cleanup and Dashboard dates.

## Install / upgrade

### CLI

```bash
npm install -g arxiv-daily@0.6.7
```

Or run `arxiv-daily update`.

### Obsidian plugin

Update through Obsidian's Community plugins interface after the matching GitHub release is available. The release assets remain exactly `manifest.json`, `main.js`, and `styles.css`.

## Compatibility

- **CLI package:** `arxiv-daily@0.6.7`.
- **Node.js:** 20.19.0 or newer for the CLI and plugin; Node.js 22 is also supported.
- **Obsidian minimum version:** unchanged at `1.5.7`.
- **CLI config:** unchanged, `schema_version = 1`.
- **Plugin data:** unchanged.
