# arXiv Daily v0.2.0 Release Notes

> Release date: 2026-07-06

## Overview

v0.2.0 is a major maintenance release focused on reliability, performance, and security. The scheduler has been fundamentally refactored for correctness, the bundle size has been significantly reduced, and dozens of edge-case bugs have been fixed across timezone handling, file I/O, cancellation, and the Dashboard UI.

**Highlights:** scheduler no longer stalls after cancellation, files can't be truncated by crashes, papers with unusual metadata can't break out of LLM prompts, scheduling windows now work across midnight, and the plugin bundle is ~80% smaller.

---

## What's Changed

### Scheduler & Run Management

- **Cancellation no longer breaks scheduling.** Previously, cancelling a run would permanently disable the scheduler until manual recovery. Cancellation is now scoped per-batch — cancelling one tick or manual run leaves all future and unrelated runs unaffected.
- **`running` states auto-recover.** If Obsidian crashes or the plugin is unloaded mid-run, the date is stuck in "running" status. On next startup, the scheduler now detects and recovers dates stuck in "running" for more than 1 hour.
- **Pending results preserve attempt counters.** When a pipeline result is "pending" (e.g. no papers from arXiv that day), the attempt counter is now preserved instead of reset. This means transient failures correctly escalate to permanent after the configured threshold (10 attempts), rather than retrying indefinitely.
- **Attempt escalation is now consistent.** When a transient failure escalates to permanent after hitting the retry limit, both the store status and the history record now correctly reflect "failed_permanent" — previously the history record could show a mismatch between result kind and persisted status.
- **Tick loop is re-entrant-safe.** If a tick takes longer than the scheduled interval, overlapping ticks are now skipped instead of piling up.
- **`forceRunForDate` / `retryFailedInLookback` are lock-safe.** A race condition where these operations cleared date state outside the run lock — potentially allowing duplicate concurrent runs — has been fixed.

### Pipeline & LLM

- **OpenAI SDK removed.** The plugin no longer bundles the `openai` npm package (~2 MB). Chat completion requests are now made via raw HTTP/fetch calls, preserving full OpenAI API compatibility. The plugin bundle is now ~250 KB (down from >2 MB).
- **Cancellation actually stops HTTP.** AbortSignal is now properly propagated to arXiv API requests and metadata fetches. Cancelling a run immediately interrupts in-flight network requests instead of waiting for them to complete.
- **New `cancelled` result variant.** When the user cancels a run, it is now recorded as `cancelled` (not `failed_transient`), so the scheduler won't automatically retry a run the user chose to cancel.
- **Stream idle timeouts are retryable.** A stalled LLM stream that times out now produces a retryable error rather than being misclassified as a user cancellation (which would skip retries).
- **Better model listing errors.** When fetching available models fails, the error message now includes the status code from the endpoint, making it easier to distinguish authentication failures from network issues.
- **Partial category failures are logged.** If some arXiv categories fail but others succeed, the pipeline now logs which categories failed at `error` level.

### File I/O & Data Integrity

- **Atomic file writes.** All markdown file writes (daily reports, paper details, paper notes, frontmatter updates) now use a write-temp-then-rename pattern. If the plugin crashes mid-write, the previous file content is preserved rather than leaving a truncated file. Stale `.tmp` files are cleaned up at plugin startup.
- **State store crash recovery improved.** The run-state JSON loader now checks for `.bak` files when the primary file is missing, closing a crash window that could previously cause complete state loss.
- **Run history malformed lines are now logged.** If a history file contains truncated JSON (from a previous crash), the malformed lines are logged at `warn` level with a preview, rather than being silently dropped.

### Time & Date Handling

- **Cross-midnight scheduling windows now work.** A scheduler window configured as `23:00–02:00` (overnight) now correctly activates at 11 PM and deactivates at 2 AM — previously it silently never fired.
- **Weekend detection is timezone-aware.** The `isWeekendDate` function now respects the configured timezone instead of computing from UTC, which could be off by one day for timezones near the UTC boundary.
- **Date arithmetic is timezone-aware.** `daysBefore` calculations now use the configured timezone, fixing off-by-one-day bugs for timezone-boundary dates.
- **All callers updated.** Scheduler lookback, dashboard calendar rendering, date selection, and diagnostics all pass the user's timezone for consistent date handling.

### Dashboard & UI

- **Faster tab/filter switching.** Switching tabs, changing filters, or toggling the "Detail summary" filter now only re-renders the results section instead of rebuilding the entire Dashboard (header, toolbar, tabs, calendar).
- **Calendar navigation race fixed.** Rapidly clicking prev/next month no longer causes stale data to overwrite the current month's calendar.
- **Filter badge counts update on tab switch.** The "Detail summary" filter count now correctly reflects the current tab's data when switching between "Starred" and "All".
- **Settings: duplicate model dropdown listener removed.** The model selector no longer triggers two save operations per change.
- **Settings: template warning improved.** When applying a quick-start template, the confirmation dialog now explicitly warns if arXiv categories will be overwritten.

### TypeScript & Build

- **Strict index access enabled.** `noUncheckedIndexedAccess` is now enabled in tsconfig, providing compile-time safety for array and object access across the codebase.
- **Vitest config enhanced.** `isolate: true` prevents cross-test leakage; `restoreMocks: true` clears mock state between tests; v8 coverage provider is configured.
- **Retry utility hardened.** Maximum delay is capped at 30 minutes (prevents `Infinity` overflow with high backoff factors), and jitter is added to prevent thundering-herd on retry.

### Security

- **Prompt injection hardening.** Paper titles, abstracts, and full-text sections containing `</paper_data>` are now escaped before being inserted into LLM prompts. This provides defense-in-depth: even if a paper's metadata deliberately attempts to break out of the data fence, it is rendered inert.

### Node CLI & Adapters

- **`setSecret`/`deleteSecret` implemented for Node.** The `EnvSecretProvider` now stores runtime-set secrets in memory (with a warning that they do not persist across restarts), matching the interface contract.
- **CLI unhandled rejection handled.** Top-level errors in the CLI entry point are now caught and reported with a non-zero exit code.
- **Plugin unload promise handled.** The dashboard leaf detach call in `onunload()` now catches and discards errors instead of leaving a floating unhandled rejection.

---

## Breaking Changes

None. v0.2.0 is fully backward-compatible with v0.1.21 settings, output files, and workflows.
