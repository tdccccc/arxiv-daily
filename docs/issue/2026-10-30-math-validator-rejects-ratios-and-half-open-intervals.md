# 公式校验把比例和半开区间判为格式错误，日报摘要因此重试甚至回退

状态：未修复

> 来源：摘要质量评估离线检查（PR #144），2026-10-28；已用探针脚本核实
> 严重程度：低到中 · 置信度：校验函数已复现，对日报回退的影响为代码推断

## 问题与依据

`packages/core/src/pipeline/scientific-markdown-math.ts` 的 `canonicalizeScientificMarkdownMath` 会误判两种在 Obsidian 中能正常显示的写法：

| 写法 | 校验结果 |
| --- | --- |
| `比例为 $6:1$。`、`$8:1:1$ 划分` | `unclosed-delimiter` |
| `$g \in (0, 0.15]$` | `unbalanced-parentheses` |
| `$[0,1)$` | `unbalanced-optional-argument` |
| `$0.5$`、`$10^{10}\,M_{\odot}$`、`$0.8$–$0.95$`、`$1.2\pm0.3$`、`$3\sigma$` | 通过 |

日报单篇摘要（`daily-paper-summary.ts` 的 `validateStructuredPaperSummaryValue`）用同一个函数校验每个字段。字段里只要出现上面两种写法，整条回复就被判为不合格，进入重试；重试用完后，这篇论文会以 `validation-exhausted` 回退。真实 Vault 现有 469 条日报条目里没有出现这两种写法，原因可能是它们已在生成时被拒绝并重试掉了，日志不足以区分。详细笔记不经过这个校验，离线检查在 3 篇笔记里看到了这两种写法，渲染都正常。

## 原因

- `$` 后面紧跟数字时，被当作货币符号而不是公式开头，于是后面的定界符整体错位。
- 括号平衡检查把区间记号里的 `(`…`]`、`[`…`)` 当作没有配对的括号。

## 建议和验收

- 货币判断只在确实像金额时生效。例如同一行内找不到与之配对、且前面不是空白的闭合 `$`，才把这个 `$` 当作货币符号。
- 区间记号 `(a, b]`、`[a, b)` 在公式内允许左右括号不同类。
- 原有的拒绝情形保持不变：裸 TeX、`$$`、未闭合定界符、真正不平衡的括号。

## 修复后应补的测试

在 core 的公式校验测试里补：

- 比例 `$6:1$`、`$8:1:1$` 和半开区间 `$(0, 0.15]$`、`$[0,1)$` 通过；
- 普通文本中的金额（如 `花费 $5 和 $10`）仍按原规则处理；
- 原有拒绝用例全部保持；
- 日报摘要合同测试里，含这两种写法的回复第一次就通过，不触发重试。
