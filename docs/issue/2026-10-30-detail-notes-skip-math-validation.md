# 详细笔记生成后不做公式校验，`\(..\)`、拆开的公式等直接写进 Vault

状态：未修复

> 来源：摘要质量评估离线检查（PR #144），2026-10-28
> 严重程度：低到中 · 置信度：离线检查对真实 Vault 已复现

## 问题与依据

日报单篇摘要的每个字段都要经过 core 公式校验（不合格就重试），离线检查在 469 条日报条目里没有发现任何公式问题。详细笔记走 `packages/core/src/pipeline/summarizer.ts` 的 `summarizePaperDetail`，只检查输出不为空，提示词里的公式规则没有程序把关。

离线检查对真实 Vault 46 篇当前格式笔记的结果：7 篇有真问题，另有 3 篇是 core 规则误报（见 [比例与半开区间误判](2026-10-30-math-validator-rejects-ratios-and-half-open-intervals.md)）。真问题如下：

| 问题 | 次数 | 例子 |
| --- | --- | --- |
| `\(..\)` 或多行 `\[..\]` | 51 | 2606.17371 用了 22 次 `\(\Delta p\)` |
| 一个公式被拆成两段，括号跨段 | 12 | 2607.06977：`$(2.34$–$2.95\,\mathrm{keV})$` |
| 公式外出现 TeX 命令 | 4 | 2606.17984：`\texttt{mizuki}` |
| 定界符错位 | 1 | 2606.17044："通过$-射线"，`$\gamma$` 丢了内容 |

这些笔记都生成于 2026-07 以前，用的是旧版提示词和旧生成模型。2026-10-29 用当前配置重新生成的 10 篇笔记还没有跑过离线检查，现在的比例未知。

报告位置：本机 `~/quality-eval/summary-2026-10-28-offline/report.md`。

## 原因

公式校验只接在日报字段的 JSON 合同上。详细笔记是整篇 Markdown，没有对应的校验或修正步骤。

## 建议和验收

- 先量化：对重新生成的 10 篇笔记跑离线检查，确认当前配置下是否仍有问题。可以把 regenerate 的输出转成 Vault 结构后用 `summary-check.mjs`，或者给检查命令加一个读取 regenerate 目录的入口。
- 如果仍有问题，在笔记写入前做一次 Markdown 级规范化：把 `\(..\)`、`\[..\]` 改写成 `$..$`、`$$..$$`；能确定的拆开公式自动合并；其余问题记警告，或带具体原因让模型重试一次。不能因此让笔记生成整体失败。
- 不改变笔记的章节结构，也不改变 Dashboard 的识别。

## 修复后应补的测试

- 笔记规范化的单元测试：`\(..\)`、多行 `\[..\]` 被改写；拆开的公式被合并；`$$` 独立公式保留；代码块不受影响。
- `summarizePaperDetail` 的集成测试：模型返回含 `\(..\)` 的笔记后，写入的是规范化后的文本。
