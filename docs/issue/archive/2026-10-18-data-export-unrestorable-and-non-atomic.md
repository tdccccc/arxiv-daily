# `data export` 能导出 `data import` 拒绝的备份，且导出会原地覆盖旧备份

> 发现日期：2026-10-18 · 来源：main `21fe2ce` 深度代码审查 · 编号 CLI-1、CLI-2
> 范围：CLI `data export` / `data import` · 严重程度：中 · 状态：已修复（分支 `fix/2026-10-18-review`，提交 7043049） · 置信度：CLI-1 已复现，CLI-2 代码推断

## 问题

### 导出的备份可能无法导入（CLI-1）

`data export` 成功退出并显示"exported N files"，但用户真正需要恢复时才发现备份用不了。触发条件任一即可：

- daily/、papers/、.index/ 合计超过 10,000 个文件（多年积累、每篇都有笔记的库会达到）；
- 单个文件超过 64 MiB；
- 解压后总量超过 512 MiB；
- 任一文件压缩比超过 200:1（例如含大段空白的笔记或索引文件）。

实测：10,100 个文件的导出无法导入。

### 导出非原子、不检查输出位置（CLI-2）

`--out backup.zip` 直接 `fs.writeFile` 覆盖已有备份。进程被杀、磁盘写满时，旧的好备份被毁，只剩一个残缺 zip。输出路径也可以落在被导出的目录里，下一次导出会把上一次的导出也打包进去。

## 原因

- `apps/cli/src/data-cmd.ts:16` `DATA_IMPORT_LIMITS` 只在导入的 `validateRawZip` / `streamZipEntry` 中执行；`dataExport`（39-87 行）不做对应检查。
- `data-cmd.ts:83`：`fs.mkdir` + `fs.writeFile(outPath, buf)`，没有临时文件 + rename，也没有包含关系检查。

## 可能的解决方案

推荐：
1. 导出使用与导入相同的限制常量，超限时在写 zip 前以明确信息失败（退出码非 0），说明哪项超限。压缩比限制按导入同样的规则预检。
2. 写入同目录临时文件（`wx`），完成后 rename 覆盖目标。
3. 输出路径解析后位于任一导出根目录内时拒绝。

备选：放宽导入对本工具产出归档的条目数限制（保留绝对字节上限），代价是削弱压缩炸弹防护。

## 修复后应补的测试

- 超过条目数 / 单文件大小的数据集导出失败并给出原因，不写出 zip。
- 导出中途失败时原有备份保持不变。
- `--out` 指向 daily/ 内时被拒绝。

## 修复情况

导出执行与导入相同的限制（条目数、单文件与总字节、压缩比），超限时在写出前失败并指明是哪项。压缩比会超过 200:1 的文件改为不压缩存储，保证备份可导入。写入走同目录临时文件（`wx` + fsync）再 rename；`--out` 位于 daily/papers/.index 内（含经由符号链接）时拒绝。
