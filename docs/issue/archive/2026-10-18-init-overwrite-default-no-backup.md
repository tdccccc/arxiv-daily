# `init` 遇到已有配置时默认"覆盖"且不备份；选"保留"也要走完整个向导

> 发现日期：2026-10-18 · 来源：main `21fe2ce` 深度代码审查 · 编号 CLI-3
> 范围：CLI `init` · 严重程度：中 · 状态：已修复（分支 `fix/2026-10-18-review`，提交 34b9b51） · 置信度：代码推断

## 问题

`config.toml` 已存在时，"Config already exists"提示的默认选项是 `o`（覆盖整个文件），直接回车就会替换。新生成的模板不含用户之后积累的任何状态：已接受的主题与方向、`[library]` 连接与处理授权、`library_proposal_acceptances`、日程、工作台日程、邮件设置。文献库授权属于用户同意记录，被悄悄抹掉后需要重新授权，而且没有任何备份。

选"保留现有"同样有问题：向导仍然问完所有问题，然后 `mergeTomlPreferExisting` 丢弃全部回答，只在文件末尾追加一行注释（每次重跑都追加一行）。如果现有文件没有 `vault_root =` 行，则直接落到新生成内容，等于"保留"变成了覆盖。

## 原因

- `apps/cli/src/init.ts:213`：`askSelect` 的 `initialValue: 'o'`。
- `init.ts:1264-1269` `mergeTomlPreferExisting` 是个桩：返回"现有内容 + 注释"，或在正则不匹配时返回新生成内容。
- `init` 也没有获取工作台配置写入使用的 cli-config 文件锁。

## 可能的解决方案

推荐：
1. 默认选项改为"保留 / 取消"。
2. 在运行向导之前询问文件处理方式，选择"保留"时直接结束，不再走向导、不再追加注释。
3. 覆盖前把原文件复制为 `config.toml.bak-<时间戳>`（权限 0600），并提示备份位置。

## 修复后应补的测试

- 已有配置 + 默认选择 → 文件不变。
- 选择覆盖 → 生成备份文件，内容与原文件一致。
- 选择保留 → 不进入向导问题，文件不变。

## 修复情况

向导开始前先问保留 / 覆盖 / 取消，默认保留。保留时立即结束、不追加任何内容（权限过宽时收紧为 0600）。覆盖时先备份为 `config.toml.bak-<时间戳>`（0600）并显示路径，并获取与工作台相同的配置锁。
