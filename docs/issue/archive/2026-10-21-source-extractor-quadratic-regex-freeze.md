# LaTeX 源码清洗里有二次复杂度的正则：一篇精心构造的 arXiv 论文可以让插件或 CLI 卡死数分钟甚至更久

> 发现日期：2026-10-21 · 来源：main `d999037` 深度代码审查 · 编号 PIPE-05
> 范围：日报流水线全文获取（没有 HTML 版本、改用源码的论文）；插件界面、CLI、阅读工作台的事件循环 · 严重程度：中 · 状态：已修复（分支 `fix/2026-10-21-batch4`，提交 04b9107） · 置信度：已复现

## 问题

2026-10-18 的 CORE-01 给源码包加了解压、条目数、`\input` 展开的预算，但清洗 LaTeX 文本的正则本身没有长度保护。源码包内容由任意 arXiv 作者控制，下面这些输入会让正则对每个起点都扫到文本末尾，总耗时与长度的平方成正比，而且是在主线程里同步执行的，卡住期间没法取消：

- 大量 `\begin{figure}` 但没有对应的 `\end{figure}`：`removeLatexEnvironments` 用 `\\begin\{figure\}[\s\S]*?\\end\{figure\}`，每个起点都向后扫完整个文件。
- 大量 `\cite[`（或 `\ref[` 等）后面没有 `]`：`plainLatex` 里的 `(?:\[[^\]]*\])?` 对每个起点都扫到文件末尾。

这些内容可以放在 `\iffalse … \fi` 里，LaTeX 会照常编译通过，arXiv 不会拒收；压缩后只有几 KB，下载上限（50 MB）、解压上限（64 MB）、单文件上限（16 MB）都不会拦住它。实测耗时（一次性测试，本机并发其他测试时测得，已删除）：

| 载荷 | 重复次数 | 大小 | 耗时 |
| --- | --- | --- | --- |
| `\begin{figure}` | 2,000 / 4,000 / 8,000 / 16,000 | 29 KB … 225 KB | 12 / 29 / 110 / 433 ms |
| `\cite[` | 2,000 / 4,000 / 8,000 / 16,000 | 13 KB … 97 KB | 22 / 78 / 304 / 1204 ms |

每翻一倍长度耗时约翻四倍。按这个增长外推，1 MB 的 `\cite[` 载荷约 2 分钟，4 MB 约半小时，16 MB（单个 .tex 的上限）是数小时。论文被入选并且没有 HTML 版本时（恶意源码很可能转换失败，天然没有 HTML），日报运行会在这一篇上卡死；缓存把源码包保留到过期，之后每次运行都会再卡一次。Obsidian 里是整个渲染进程卡住，CLI 和阅读工作台里是事件循环被占住，页面和 API 全部无响应。

## 原因

- `packages/core/src/pipeline/source-extractor.ts:372-382` `removeLatexEnvironments`：对 18 个环境名各做一次 `[\s\S]*?` 的非贪婪匹配，找不到结束标签时每个起点都扫到末尾。
- `source-extractor.ts:384-408` `plainLatex`：`\\[A-Za-z]+\*?(?:\[[^\]]*\])?\s*\{…\}`（第 395 行）和 `\cite…(?:\[[^\]]*\])?`（第 388 行）对没有闭合 `]` 的 `[` 同样是每个起点扫到末尾。
- 预算（`source-extractor.ts:33-44`）只限制“总字符数、展开次数”，没有限制单次正则扫描的代价，也没有时间或输入长度上限。

## 可能的解决方案

推荐：

1. 给清洗阶段设输入长度上限（例如处理正文前先截到几百 KB～1 MB，超出的按“源码不可用”处理），并给 `[\s\S]*?` 和 `[^\]]*` 这类扫描加有界长度（`{0,2000}`）。
2. 把 `removeLatexEnvironments` 改成线性扫描：用一次遍历找 `\begin{env}`，找不到对应的 `\end{env}` 就跳过这个起点并继续，而不是让正则回溯。
3. 可选：把源码清洗放进有超时的 worker 或让出事件循环，避免界面和 API 卡住。

备选：只加输入长度上限，改动最小，能把最坏情况压到秒级。

## 修复后应补的测试

- 64 KB～1 MB 的 `\begin{figure}` / `\cite[` / `\input{` 重复载荷，`extractLatexSource` 在固定时间内（例如 1 秒）返回或判为“源码不可用”。
- 正常多文件论文的抽取结果不变（现有 `source-extractor.test.ts` 继续通过）。

## 修复情况

未闭合环境、引用可选参数、input 与 abstract 不再对每个起点反复扫描整段尾部；正文参数配对只扫描一次。展开后超过1 MiB的源码作为不可用交给既有回退路径，避免长时间占用事件循环。24,000次未闭合引用旧实现约2.7秒，新实现四类对抗用例均低于1.5秒，正常多文件、重复包含与源码预算回归保持通过。
